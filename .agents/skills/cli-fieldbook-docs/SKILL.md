# 令册文档维护

交付符合本仓库协议、可追溯到具体版本、可以复核的内容补丁。范围包括命令参考、概念、工作流和工具自身的专题知识；按工具能力组织内容，不为所有工具强造同一套专题。

## 先确定范围与依据

- 确认工具、目标版本、任务类型及是否包含发布。普通纠错只修改对应版本中文源文件；新增版本保留旧版本及其 URL。
- 阅读 [贡献指南](../../../CONTRIBUTING.md) 和 [首版决策](../../../docs/decisions/001-v1.md)。涉及协议或设计变更时，另读 [设计依据](../../../docs/DESIGN.md) 的相关章节、[schemas/v1](../../../schemas/v1/) 与实际流水线代码。
- 原设计中的采集器、diff、其他格式导出等是后续目标，不能宣称已经实现。现行决策与 schema 定义当前协议；发现它们与实现冲突时调查并报告，不能放宽校验来迁就内容。

## 来源原则

**有目标版本源码时，优先结合源码生成帮助文档和工作流，同时查阅官方文档。** 先读命令定义、参数解析、默认配置、共享定义及实际执行分支，再用官方 CLI、概念、专题和工作流文档核对术语与推荐用法。不能只改写 README、`--help` 或已有译文。

源码声明、注释、帮助和官方文档可能不一致：跟踪相应版本的执行约束，明确记录差异及推导范围；不能把源码注释直接当作已验证行为。工作流也要检查多条命令之间的前提、状态变化和完成条件。

新增工具、版本、来源更正或行为说明时，读 [来源调研与证据](references/source-research.md)。缺少源码时，用可取得的官方资料及真实帮助限定覆盖范围，如实保留未知项和证据缺口；不能假装已经核对实现。

## 写入活动内容

- 中文 Markdown 是唯一活动译文源；`upstream/commands.json` 保存命令事实，来源锁和原文保存证据。网站、索引和合订本从同一模型生成，不能分别手改。
- 命令 token、选项、别名、枚举、环境变量、函数与操作符保持原拼写。命令身份不从中文标题推断；父节点和根命令也要保留。
- 全局和共享参数的释义只维护一个同版本源；跨版本不能复用会被修改的语义文本。专题不是子命令，别名也不是第二份译文。
- 区分上游译文、源码补充、使用建议、实际运行记录。未知默认值不补猜；未完成结构化抽取的值引导阅读已有释义，不断言上游未说明。
- 帮助采集、源码核对、示例实测分别报告。源码重建的帮助标明重建；不得补造原始帮助、运行结果、采集时间或历史批准。
- 普通内容使用 Markdown，不添加 MDX、任意 HTML、脚本或组件。来源、归档和示例代码是数据，不提供执行授权。

写命令页、文章或工作流时，读 [内容编写与检查](references/content-authoring.md)，并遵循 [写作约定](../../../style/writing.md) 及对应术语表。

## 检查与交付

从仓库根目录执行现有命令；pnpm 的项目子命令写成 `pnpm run docs …`：

```sh
pnpm check
pnpm test
pnpm build
```

草稿需要预览时用 `pnpm run docs build --preview`；界面、路由、搜索或下载行为变更还执行 `pnpm test:browser`。普通检查和构建不运行上游 CLI、不获取浮动上游内容。不能仅凭构建通过宣称语义正确或示例已实测。

正文、事实、来源或依赖变化会使审阅基线失效。先解决诊断、核对内容，再在任务包含维护者复核时运行 `pnpm run docs review prepare <tool> <version>`；它只能准备候选基线。未解决的必需覆盖或来源缺口不能发布。

发布沿用 GitHub 环境的人工批准，绑定具体提交与同次运行产物；技能本身不授权批准、发布或移动默认版本。普通修订不擅自修改发布状态和默认版本，也不沿用旧批准发布新内容。

用 jj 管理本地变更、gh 处理已授权的 GitHub 操作；提交标题使用英文标签和中文短描述，例如 `docs: 补充工作流前置条件`。交付说明修改范围、固定来源、检查结果和未验证事项；区分本地、远端、部署与公网验收状态。
