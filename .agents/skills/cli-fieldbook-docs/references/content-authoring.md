# 内容编写与检查

从仓库根目录定位 `catalog/<tool>/versions/<version>/zh-CN/`。普通译文编辑留在该目录；命令事实或来源有误时，提交可追溯的来源更正或修正导入逻辑，不手改生成网站来掩盖问题。

## 命令、概念与专题

命令身份使用原始 token 数组，一节点一文件：根命令为 `commands/index.md`、`command: []`；分组有自己的 `index.md`；真实的 index 子命令为 `commands/index/index.md`。特殊文件名用受校验的 `slug`，保留原始命令 token。

命令页填写 `## 简介`。有位置参数或本地选项时，在 `## 参数`、`## 选项` 下用三级标题填写规范名称的释义，例如 ``### `--json` ``。与参数事实对应，别名、默认值等从模型生成。隐藏、条件编译或内部入口明确说明适用范围；别名不另建一份独立译文。

全局继承选项在声明入口解释一次；共享参数链接到该版本内的唯一释义源。概念和专题用独立文章，不把表达式函数、操作符或查询语言硬塞进命令树。只维护实际覆盖的范围，例如已有 Fileset／Template 速查不等于完整专题。

文章 frontmatter 必需 `title`，可选 `uses`、`identifiers`。命令 frontmatter 必需 `command`。只使用对应 [schema](../../../../schemas/v1/) 支持的字段；不添加自证的 verified/reviewed 标签。

`uses` 引用同工具、同版本实体；命令常用 `command:status`，专题可用 `reference:revset/functions/parents`。这些是形式示例，添加前必须确认当前版本真的有该实体。依赖用于触发复核，尤其要补充正文链接无法表达的行为前提；自动提取不能证明依赖已穷尽。

同版本文章间用相对 Markdown 链接；稳定命令引用可用 `[状态](cli:command:status)`。真实网页 URL 和项目 base 由流水线生成，不把 `.md` 路径或 `cli:` 原样塞进生成页面。函数、操作符等用 `identifiers` 提供检索原值。

## 工作流应可理解、可检查

工作流从目标和前提开始，再解释每步为何存在。至少交代相关的工作目录、仓库／会话状态、配置、环境、版本或构建特性；可选前提只在影响行为时写入。

每条示例使用已核对的命令、参数和专题语法。标出占位符和输入来源，说明作用范围、状态变化、输出如何供下一步使用，以及如何判断结束。涉及异步任务时区分“请求接受”和“任务完成”；超时也不自动意味着失败或已经取消。

提供有依据的失败／恢复说明。不要无条件重试会产生副作用的操作，也不要把隐藏调试入口推荐成稳定工作流。未实测的工作流仍可基于源码与官方文档编写，但明确未实测；预期输出与真实运行结果分开。

沿用 [写作约定](../../../../style/writing.md)，工具术语优先查 `style/tools/<tool>.yml`，再查 [通用术语](../../../../style/terms.yml)。中文解释准确简洁，命令标识与可复制语法保持原值。

## 新工具与新版本

下面的 `democtl` 是虚构示例。使用真实任务参数替换工具、版本和来源路径，在仓库根目录运行：

```sh
pnpm run docs new-tool democtl --name Demo --repository https://example.com/democtl
pnpm run docs new-version democtl 1.0.0 --ref v1.0.0
pnpm run docs import democtl 1.0.0 --input ./capture-data
```

`--input` 协议目录包含版本声明、固定来源锁、命令事实、来源文本及可选中文内容。只有两个命名旧资料适配器接受历史 ZIP；其他工具走协议目录。导入冲突停止处理，不覆盖已有来源版本。

新版本可用 `new-version … --from <previous>` 复用中文源，随后导入目标版本的来源并复核。它不复制旧来源或审核批准。工具与版本从目录发现，不新增前端注册表；保留旧版本，默认版本由维护者明确决定。

## 处理检查与审阅

`pnpm run docs check --json` 输出文件位置、错误码与修复建议，默认只读。区分草稿警告与公开版本错误；不要为消除诊断自动改来源摘要、移动默认版本或削弱 checker/schema。

内容变化若报 `review_required`，核对正文、命令事实、固定来源与声明依赖，再由承担本次维护者复核的任务执行 `review prepare`。`review.lock.json` 只能为 `prepared`；正文和依赖有变化，就不能沿用旧指纹。修改基线本身不是证明已经审核。

构建后的页面、搜索与 Markdown 下载共用模型。按任务检查根／父命令、别名、全局继承、字段、专题依赖、草稿排除以及旧链接；涉及展示行为时覆盖明确版本 URL、项目 base、搜索过滤、下载、键盘与手机导航。

自有代码和原创中文说明遵循仓库 Apache-2.0；上游材料保留原有归属与许可边界。发布申请与 GitHub 环境批准遵循 [首版决策](../../../../docs/decisions/001-v1.md)，不能因文档或 skill 写着“已审核”而绕过最终批准。
