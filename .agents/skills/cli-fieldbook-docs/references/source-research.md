# 来源调研与证据

用于新工具／版本、来源更正、命令行为解释和工作流编写。目标是让重要结论能回到具体证据，而不是堆积大量链接。

## 固定版本，交叉阅读

先查看目标目录的 `version.yml`、`upstream/source.lock.json`、原文快照和命令清单。可用源码优先来自对应完整提交的本地文件或已锁定快照；新取得的原文保存原字节及准确摘要。工具版本、文档修订和 schema 版本是不同标识。

官方文档也必须阅读相关部分：CLI reference 核对用户入口，概念文档核对对象与术语，专题参考核对函数和操作符，教程核对工作流意图。优先取得相同版本的文档；只有滚动 latest 时标明这一限制，逐项用固定源码核对相关结论。不能把当前 main/latest 的行为直接写进历史版本。

| 核对对象 | 应查看的证据与常见遗漏 |
| --- | --- |
| 命令树与身份 | 根入口、子命令注册、父组、别名及默认动作；公开、隐藏、内部与条件编译入口分开统计 |
| 参数与选项 | 解析声明、规范拼写、短长别名、必需项、数量、互斥、可选值；展开 flatten／共享结构，追到父模块或真正定义处 |
| 默认行为 | 内置配置、配置合并顺序、环境变量和运行分支；区分内置默认值与用户的有效值 |
| 行为边界 | 实际分发和错误分支、退出码、超时、重试、副作用、平台／feature 限制；不只阅读声明旁注释 |
| 专题知识 | 语法／操作符定义、函数注册与实现、默认别名、官方概念说明；不能由名称猜语义 |
| 多命令工作流 | 每步要求的仓库／会话状态、输入输出关系、同步或异步完成、失败恢复；官方示例不能替代实现约束核对 |

源码用于判断该版本的实现约束；官方文档用于解释接口意图和推荐用法；真实帮助反映特定二进制／构建的输出。发生矛盾时记录两边位置和差异，说明正文采用的依据。证据无法消解的冲突保留待确认，不伪造确定结论。

## 保存证据与验证边界

固定源码链接使用完整提交 SHA；行号从实际保存的同一文件核对，不能复用其他版本行号。字段的 `evidenceIds` 应指向真正声明或实现它的证据，不满足于顶层仓库链接。保留上游版权、LICENSE/NOTICE 和非官方整理标识。

来源锁按 [当前 source schema](../../../../schemas/v1/source.schema.json) 填写。当前实现支持 `source-snapshot` 与 `legacy-import`；不支持的采集记录要通过明确的协议演进解决，不能往严格 schema 中塞入自创字段。官方仓库文档也可以保存为固定来源快照。

没有源码时，说明实际使用了哪些官方文档或真实帮助、对应版本／构建条件，以及哪些行为没有实现证据。不可取得材料时记录缺口；新版本保持草稿，直至必需来源与覆盖满足协议。少量纠错仅核对受影响结论，不无故扩大到全工具审计。

分别说明帮助是否真实采集、源码核对范围、哪些示例真实执行过。不要把旧资料的历史调研叙述当作本轮新完成的验证；普通重建不更新来源取得时间。完整覆盖必须说明分母与排除项，不能把“已有清单全部有译文”换算成整个工具的 100%。

可以用以下短表组织本轮关键结论；它是审阅笔记形状，不是新增 schema 或强制新增报告文件：

| 结论／实体 | 固定源码定位 | 官方文档依据 | 差异或限制 | 本轮验证 |
| --- | --- | --- | --- | --- |
| 待核对项 | 文件、定义及完整提交 | 对应版本章节或注明滚动页面 | 前提／feature／缺口 | 阅读核对或具体实测 |

原始帮助只有实际采集后才能标记为原始输出。源码重建视图由现有流水线生成，不另写假 `raw-help`。运行示例只在任务授权、明确选择且隔离的验证环境中进行；普通检查／构建不执行上游程序或归档脚本，也不抽取 Markdown 中所有 shell 批量执行。

## 现有材料迁移

按原章节与实体建立迁移对应，检查漏页、重复知识和旧链接。原包保留为只读档案；HTML、TXT 和采集脚本不成为活动编辑源。去重后保留访问指向，不能把实际章节或函数链接统统降级到历史资料说明页。

已有语义解释可以复用，但必须重新核对受影响的固定来源；迁移格式不产生新的实测或维护者批准。[首版审核报告](../../../../docs/AUDIT.md) 提供现有两工具的来源范围与发现记录，不作为以后新版本已经通过审核的证明。
