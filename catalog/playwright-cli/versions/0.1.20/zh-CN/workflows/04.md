**适用场景：** 手工登录一次，之后的新会话免登录直接进入已认证状态；或检查/修改页面的 cookie 与本地存储。

## 前提

- 已有会话并完成登录（或将要登录）。
- 准备一个状态文件名（如 `auth.json`），存放位置按敏感数据处理。

## 步骤

### 1. 登录并保存状态

```sh
playwright-cli open https://example.com/login
playwright-cli fill e1 "user@example.com"
playwright-cli fill e2 "password123" --submit
playwright-cli state-save auth.json
```

登录成功的完成信号是跳转后快照显示已登录界面；[state-save](cli:command:state-save) 把当前 cookie 与 localStorage 导出为 JSON 状态文件（与 Playwright 测试的 `storageState` 同一格式）。

### 2. 新会话恢复状态

```sh
playwright-cli close
playwright-cli open https://example.com
playwright-cli state-load auth.json
playwright-cli reload
```

[state-load](cli:command:state-load) 应用状态文件后，刷新或导航即以已登录身份请求。完成信号：快照显示登录态界面。

### 3. 检查与微调存储

```sh
playwright-cli cookie-list --domain=example.com
playwright-cli --raw cookie-get session_id
playwright-cli localstorage-list
playwright-cli localstorage-set theme dark
```

三层存储（cookie / localStorage / sessionStorage）各有 list/get/set/delete/clear 五件套；list/get 为 raw 输出，可直接入变量。

### 4. 失效处理

状态文件对应的会话在服务端过期时，恢复后请求会被重定向到登录页——重新执行步骤 1。会话本身被站点踢出时同理。

**风险与边界：** 状态文件包含会话凭据，不要提交进版本库或作为附件外发；`cookie-clear`/`localstorage-clear` 清空当前层全部数据，作用范围是当前会话页面。
