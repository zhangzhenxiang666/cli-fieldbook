**适用场景：** 排查页面行为问题：看它发了哪些请求、返回了什么、控制台报了什么；或反过来，用模拟响应稳定复现某后端行为。

## 前提

- 会话已打开目标页面（或先 [route](cli:command:route) 再导航，让拦截覆盖首次加载）。
- 知道要排查的接口 URL 模式（如 `**/api/users`）。

## 步骤

### 1. 列出请求

```sh
playwright-cli requests
playwright-cli requests --static --filter "/api/.*user"
```

默认不含成功的静态资源；`--filter` 按正则缩小范围。每条请求带 1 起始序号。完成信号：列表包含目标请求及其序号。

### 2. 查看单条详情

```sh
playwright-cli request 5
playwright-cli response-body 5
```

[request](cli:command:request) 给完整四段（请求头/请求体/响应头/响应体）；分侧命令（[request-headers](cli:command:request-headers) 等）只取一段，文本体内联、二进制存文件。

### 3. 看控制台

```sh
playwright-cli console
playwright-cli console warning
```

`min-level` 提升到 `warning`/`error` 过滤噪音。完成信号：定位到报错对应的请求或脚本。

### 4.（按需）mock 响应复现问题

```sh
playwright-cli route "https://api.example.com/**" --status=500
playwright-cli reload
playwright-cli unroute
```

[route](cli:command:route) 让命中模式的请求直接返回指定状态码/响应体，重载页面即可复现失败分支；[unroute](cli:command:unroute) 移除。`--body` 给 JSON 体时配合 `--content-type=application/json`。

**状态变化一览：**

| 命令 | 对后续请求的作用 |
| --- | --- |
| `route <pattern>` | 命中模式的请求不再发往网络 |
| `unroute <pattern>` / `unroute` | 移除匹配路由 / 全部路由 |
| `requests --clear` | 清空请求列表（序号重新计数） |

**风险与边界：** 路由持续到 unroute 或会话关闭，排查完记得移除，否则后续观察仍在看 mock 数据。
