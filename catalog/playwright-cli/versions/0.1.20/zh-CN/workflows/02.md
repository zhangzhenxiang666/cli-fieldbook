**适用场景：** 在已打开的会话中完成一次表单填写提交，并从结果页提取结构化数据。这是 agent 驱动页面的典型循环：快照定位 → 填写 → 提交 → 提取。

## 前提

- 已按[工作流 01](01.md)建立会话，目标表单页已打开。
- 知道表单的提交后行为（跳转、弹窗或原地更新），用于判断完成信号。

## 步骤

### 1. 拍快照定位表单元素

```sh
playwright-cli snapshot
```

从快照中找到各输入框的引用（如 `e1` 邮箱、`e2` 密码、`e3` 提交按钮）。大表单可用 `--depth=4` 限深或 [find](cli:command:find) 检索标签文本。

### 2. 填写并提交

```sh
playwright-cli fill e1 "user@example.com"
playwright-cli fill e2 "password123"
playwright-cli click e3
```

[fill](cli:command:fill) 一次性设值（`--submit` 可在填完后按 Enter）；需要模拟逐键输入用 [type](cli:command:type)。提交触发的对话框用 [dialog-accept](cli:command:dialog-accept)/[dialog-dismiss](cli:command:dialog-dismiss) 处理。

### 3. 确认结果并提取数据

```sh
playwright-cli snapshot
playwright-cli --raw eval "JSON.stringify([...document.querySelectorAll('a')].map(a => a.href))" > links.json
```

提交后的自动快照确认页面状态；[eval](cli:command:eval) 在页面上下文求值提取数据，`--raw` 加重定向把纯结果落盘。

### 4.（按需）文件上传

```sh
playwright-cli click e4
playwright-cli upload /abs/path/document.pdf
```

先点击触发文件选择框，随后 [upload](cli:command:upload) 提供文件。完成信号：页面显示已选文件名。

**风险与边界：** 引用在页面结构变化后可能失效，失效时重新拍快照；`eval`/[run-code](cli:command:run-code) 执行任意页面代码，片段内容应可审查；真实站点的提交有副作用，先用测试环境验证。
