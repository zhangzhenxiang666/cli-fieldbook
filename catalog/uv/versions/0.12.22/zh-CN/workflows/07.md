**适用场景：** 把库或应用构建为 sdist 与 wheel，并上传到索引（默认 PyPI）。适用于 `pyproject.toml` 声明了构建后端的项目。

## 前提

- 工作目录是项目根（或给 [uv build](cli:command:build) 传入目录／sdist 归档路径）。
- 发布需要索引凭据：下文用 PyPI API token 为例，`<token>` 为占位符，不要把真实 token 写进脚本或命令历史。
- uv 0.12.22 的 `uv init` 默认应用模板已带 `[build-system]`；旧式无构建系统的项目不会被安装为包。

## 步骤

### 1. 构建

```sh
uv build
uv build --sdist
uv build --wheel
uv build --sdist --wheel
```

默认（传入目录时）先从源码目录构建 sdist，再**从该 sdist** 构建 wheel——这验证了 sdist 足以重建 wheel。`--sdist`／`--wheel` 只构建其一；`--sdist --wheel` 则两者都直接从源码构建。传入 sdist 归档并加 `--wheel` 时，从归档构建 wheel。产物默认写入源目录下的 `dist/`，`--out-dir` 改变输出位置，`--clear` 先清理陈旧产物（输出目录默认生成 `.gitignore` 以排除构建产物，`--no-create-gitignore` 关闭）。构建在隔离环境中进行，`--python` 选择构建用解释器，`-c <constraints>` 约束构建依赖。

发布前的官方建议：运行 `uv build --no-sources` 验证禁用 `tool.uv.sources` 时也能构建成功——其他构建前端（如 `pypa/build`）不认识 uv 的 sources 表。

### 2. 准备认证

```sh
export UV_PUBLISH_TOKEN=<token>
```

PyPI token 认证等价于 `--username __token__` 加 `--password <token>`，可直接用 `uv publish --token <token>`，或走环境变量 `UV_PUBLISH_TOKEN`（推荐，避免留在 shell 历史）。在 GitHub Actions／GitLab CI 中可改用 trusted publishing 免 token。

### 3. 发布

```sh
uv publish
uv publish --dry-run
```

默认上传 `dist/*` 中的 wheel、sdist 及其证明文件，忽略其他文件。`--dry-run` 只做本地元数据校验（以及 `--check-url`／`--index` 给定时的重复检查），不上传。上传端点默认是 PyPI 的 `https://upload.pypi.org/legacy/`；其他索引用 `--publish-url`，或在配置中命名索引后用 `--index <name>`（其 `publish-url` 同时提供查重地址）。

**执行结果与完成判断：** 命令成功退出且每个文件都报告上传完成才算发布完成。部分失败时用 `--check-url <index-url>` 重试：上传前先查索引，已存在的相同文件会被跳过，因此只补传缺失的文件，而不是无条件重复全量上传（PyPI 对重复上传同一文件本就宽容，多数其他索引会报错）。

**风险与边界：** `uv publish` 无法离线运行（该命令隐藏了全局 `--offline`）。默认随分发上传 PEP 740 证明文件，`--no-attestations` 关闭。构建产物的版本号来自项目元数据，发布前确认 `pyproject.toml` 中的版本已递增。

**未实测声明：** 本工作流依据 uv 0.12.22 固定提交的源码与官方文档快照编写，命令组合未在真实环境实测；`<token>`、`<name>`、`<index-url>` 为占位符。
