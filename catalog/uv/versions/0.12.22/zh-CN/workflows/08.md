**适用场景：** 控制 uv 缓存的位置与体积、制定 CI 缓存策略，以及在离线或需要绕过缓存时正确选择全局选项。`--offline`、`--no-cache`、`--refresh` 都是根命令 [uv](cli:command:) 上的全局／缓存选项。

## 前提

- 已安装 uv 0.12.22。uv 始终需要缓存目录：即使 `--no-cache`，也会用一次性的临时缓存在单次调用内共享数据。
- 下文 `<package>` 表示任意包名。

## 步骤

### 1. 查看缓存

```sh
uv cache dir
uv cache size
```

[uv cache dir](cli:command:cache/dir) 显示缓存目录：默认 Unix 为 `$XDG_CACHE_HOME/uv` 或 `$HOME/.cache/uv`，Windows 为 `%LOCALAPPDATA%\uv\cache`；可用 `--cache-dir`、`UV_CACHE_DIR` 或 `tool.uv.cache-dir` 覆盖。[uv cache size](cli:command:cache/size) 显示总体积（终端下人类可读格式，否则原始字节数）。性能要点：缓存目录应与目标 Python 环境在同一文件系统上，否则 uv 无法用链接方式安装，退化为慢速复制。

### 2. 清理

```sh
uv cache clean
uv cache clean ruff
```

[uv cache clean](cli:command:cache/clean)（别名 `clear`）不带参数清除全部缓存条目；带包名只清这些包的条目，适合"单个包的缓存可疑"的场景。清理会阻塞到没有其他 uv 进程在读缓存，默认最多等待 5 分钟（`UV_LOCK_TIMEOUT` 调整）；确认没有并发 uv 时才用 `--force` 跳过锁。注意 `uvx` 的临时工具环境就存在缓存里：clean 会一并删除，下次调用自动重建。

### 3. 修剪

```sh
uv cache prune
uv cache prune --ci
```

[uv cache prune](cli:command:cache/prune) 删除未被使用的条目与集中式项目环境（后者按需重建），可以安全地定期执行。`--ci` 面向持续集成：移除预构建 wheel 与解包的源码分发包，但保留从源码构建出的 wheel——官方建议在 CI 任务结束时执行，使持久化缓存的收益最大。

### 4. 离线

```sh
uv sync --offline
```

`--offline`（环境变量 `UV_OFFLINE`）让 uv 只使用本地缓存与本地文件。有依据的失败恢复：依赖未缓存时命令直接失败，正确做法是退出离线模式补齐缓存后再次离线运行，而不是反复重试同一命令。另注意依赖审计类命令（如 `uv audit`）需要网络，无法离线执行。

### 5. 绕过与刷新缓存

```sh
uv sync --no-cache
uv sync --refresh
uv pip install --refresh-package ruff <package>
```

`--no-cache` 本次调用改用临时缓存，进程退出即弃。官方建议多数场景优先 `--refresh` 而非 `--no-cache`：`--refresh` 不读缓存但会把结果写回缓存，惠及后续操作；`--refresh-package <package>` 只刷新单个包。遇到"新发布的版本没被采纳"这类疑似缓存问题时，按代价从小到大尝试：`--refresh`（或 `--refresh-package`）→ `--reinstall` → `uv cache clean <package>`，不要一上来就清空整个缓存。

**风险与边界：** uv 的缓存是追加式且线程安全的，多个 uv 命令可以并发运行（安装时对目标环境加文件锁）；但**绝不要手动删改缓存目录中的内容**。缓存按桶版本化，多个 uv 版本共用同一缓存目录是安全的，桶版本不兼容时各自持有独立条目。

**未实测声明：** 本工作流依据 uv 0.12.22 固定提交的源码与官方文档快照编写，命令组合未在真实环境实测；`<package>` 为占位符。
