**适用场景：** 在空目录里从零建立一个 Python 项目：生成项目骨架、声明依赖、在隔离环境中运行，并手动同步环境。面向 uv 0.12.22 的默认"应用"模板。

## 前提

- 目标目录为空：其中不能已有 `pyproject.toml`，否则 [uv init](cli:command:init) 会报错退出。
- 已安装 uv 0.12.22，且能访问默认索引。Python 解释器不必预先安装：需要时 uv 会自动下载受管版本。
- 下文以 `example-app` 为项目名（请替换为你自己的名字），`<package>` 表示任意包名。

## 步骤

### 1. 初始化项目

```sh
uv init example-app
cd example-app
```

0.12.x 的默认模板是"应用"：创建 `pyproject.toml`、`README.md`、`.python-version`（记录发现到的解释器次版本号）和 `src/example_app/__init__.py`，并默认初始化 Git 仓库（`--vcs none` 跳过；`--bare` 只生成 `pyproject.toml`，连版本控制也不初始化）。生成的 `pyproject.toml` 形如：

```toml
[project]
name = "example-app"
version = "0.1.0"
description = "Add your description here"
readme = "README.md"
requires-python = ">=3.11"   # 下界取自发现到的解释器版本
dependencies = []

[project.scripts]
example-app = "example_app:main"

[build-system]
requires = ["uv_build>=0.12.22,<0.13"]
build-backend = "uv_build"
```

注意两点：v0.12 起应用默认声明构建后端并把源码放进 `src/`（旧教程描述的无构建系统布局需 `--no-package`）；`.venv` 与 `uv.lock` 在这一步都**不会**创建——它们在首次加锁/同步时惰性创建。若父目录中已有 `pyproject.toml`，本项目会被纳为其 workspace 成员，不希望如此时加 `--no-workspace`。

### 2. 添加依赖

```sh
uv add httpx
```

状态变化分三层：`pyproject.toml` 的 `project.dependencies` 写入带下界的约束（如 `httpx>=0.27.2`，版本号取解析时的最新兼容版本，默认 `>=` 下界）；随后解析生成 `uv.lock`（首次创建）；再把 lockfile 中的包安装进 `.venv`（首次创建）。`--frozen` 只写 `pyproject.toml` 不更新 lockfile，`--no-sync` 跳过环境安装。

有依据的失败恢复：约束无解时（例如 `uv add "httpx>9999"`）解析失败，输出 `No solution found when resolving dependencies`；修正版本范围后重试即可，不要用 `--frozen` 绕过校验（那会把未验证的依赖原样写进 `pyproject.toml`）。

### 3. 运行

```sh
uv run example-app
```

[uv run](cli:command:run) 在执行前确保项目环境存在且最新（必要时自动加锁并同步）。被执行的命令可以来自项目环境（如上例的 `[project.scripts]` 入口），也可以是外部命令（如 `uv run bash scripts/foo.sh`）。文档示例的预期输出：

```console
Hello from example-app!
```

注意 `uv run` 默认是"非精确"同步：保证所需包就位，但不删除环境中的多余包（`--exact` 切换为精确删除）。区分"命令成功"与"任务完成"：uv 的退出码跟随被执行的命令，见到预期输出才算任务完成。

### 4. 手动同步

```sh
uv sync
```

[uv sync](cli:command:sync) 执行精确同步：按 `uv.lock` 安装，并移除环境中不在 lockfile 里的包（`--inexact` 保留多余包）。`.venv` 不存在则创建。默认包含 `dev` 依赖组（PEP 735 `[dependency-groups]`），可用 `--extra`、`--group`、`--no-dev` 调整选择。项目本身以 editable 方式安装。同步前默认会重新加锁，除非给出 `--locked` 或 `--frozen`；`uv sync --check` 只校验环境是否与项目同步，不达标即报错。

**状态变化一览：**

| 命令 | pyproject.toml | uv.lock | .venv |
| --- | --- | --- | --- |
| `uv init` | 创建 | 不创建 | 不创建 |
| `uv add` | 修改依赖 | 创建／更新 | 创建／更新 |
| `uv run` | 不修改 | 按需自动更新 | 按需自动更新 |
| `uv sync` | 不修改 | 默认重新加锁 | 创建／精确同步 |

`uv.lock` 应提交版本控制：它是跨平台的通用 lockfile，由 uv 维护，不要手工编辑；`.venv` 不应提交，uv 会在其中写入内部 `.gitignore` 自动排除。

**风险与边界：** `uv.lock` 不会因为上游发布了新版本而被视为过期——升级依赖必须显式执行 `uv lock --upgrade` 或 `uv add --upgrade-package <package>`。手工编辑 `pyproject.toml` 的依赖声明是允许的，下次 `uv run`／`uv sync` 会自动重新加锁。

**未实测声明：** 本工作流依据 uv 0.12.22 固定提交的源码与官方文档快照编写，命令组合与预期输出未在真实环境实测；示例中的版本号以解析当时为准。
