**适用场景：** 项目需要一个或多个特定 Python 版本：查看可用版本、安装受管版本、把版本固定到 `.python-version`，并理解升级补丁版本后 venv 的自动切换边界。

## 前提

- 已安装 uv 0.12.22。uv 自行安装的 Python 称为"受管"（managed）版本；系统已有或其他工具（如 pyenv）安装的一律视为"系统"版本。
- 默认偏好是优先使用已装的受管版本，其次系统版本，实在没有才下载受管版本；默认还会在需要时自动下载 Python（`--no-python-downloads` 关闭）。

## 步骤

### 1. 查看与安装

```sh
uv python list
uv python list 3.13 --only-installed
uv python install 3.12
uv python install 3.9 3.10 3.11
uv python install '>=3.8,<3.10'
```

[uv python list](cli:command:python/list) 默认同时列出已安装版本与当前平台的最新补丁下载项（旧补丁与其他平台默认隐藏，`--all-versions`／`--all-platforms` 展开）。[uv python install](cli:command:python/install) 支持精确版本、次版本（装最新补丁）、约束范围与一次多个版本；不带参数时读取 `.python-version`／`.python-versions`，都没有则安装最新稳定版。安装位置：Unix 的 `~/.local/share/uv/python`，并默认把 `python3.12` 这类可执行文件装入 `~/.local/bin`（`--default` 额外提供 `python3`／`python`；uv 不会覆盖非自己管理的可执行文件，除非 `--force`）。

### 2. 固定项目版本

```sh
uv python pin 3.12
uv python pin --global 3.12
```

[uv python pin](cli:command:python/pin) 把版本请求写入当前目录的 `.python-version`（`--global` 写用户配置目录，`--rm` 移除）；不带参数则显示当前固定值，不存在时报错。固定值会与所在 workspace 的 `requires-python` 校验兼容性，不兼容即报错（`--no-project` 跳过校验）。建议只写纯版本号（如 `3.12`），便于 pyenv 等工具兼容——uv 支持的请求语法更宽。`.python-version` 的查找从工作目录向上进行，但不会越过项目／workspace 边界（用户配置目录除外）。

### 3. --python 请求语法

多数 uv 命令接受 `--python`（短写 `-p`）。常用格式：`3`、`3.12`、`3.12.3`；版本范围 `>=3.12,<3.13`；带变体 `3.13t`、`3.12.0d` 或 `3.13+freethreaded`；实现名 `cpython`／`cp`；组合 `cpython@3.12`、`cp312`；也可以直接给解释器路径或可执行文件名。完整清单见 [uv python](cli:command:python)。

### 4. venv 与升级后的重建注意

```sh
uv venv --python 3.11
uv python upgrade 3.12
```

[uv venv](cli:command:venv) 请求的版本缺失时会自动下载再创建环境。补丁升级（[uv python upgrade](cli:command:python/upgrade) 只支持受管 CPython、只升补丁不跨次版本；不卸载旧补丁）之后，uv 创建的 venv 会自动使用新补丁版本，但有三条例外，均来自源码与官方文档说明：

1. 创建时**显式指定了补丁版本**的环境（如 `uv venv -p 3.10.8`）不会透明升级。
2. 在升级功能加入之前创建的旧环境会继续使用旧版本；要启用自动升级，必须删除并重建该环境。
3. 自动升级依赖次版本目录的符号链接（如 `cpython-3.12-macos-aarch64-none` 指向具体补丁）。若其他工具把解释器路径规范化（解析了符号链接）再用它建 venv，该 venv 不会自动升级。

因此"升级了 Python 但环境还在旧版"时的恢复路径是：确认固定与请求版本，删除旧 `.venv` 后重新 `uv sync`（或重新 `uv venv`），而不是反复执行升级命令。

**风险与边界：** 可下载的 Python 版本清单随 uv 发布冻结，装新版本可能需要先升级 uv。卸载某个 venv 正在使用的 Python 会破坏该环境。跨次版本（3.12 → 3.13）不会透明升级，因为那会影响依赖解析。

**未实测声明：** 本工作流依据 uv 0.12.22 固定提交的源码与官方文档快照编写，命令组合未在真实环境实测；版本号请替换为实际需要的值。
