**适用场景：** 把既有的 pip／pip-tools／virtualenv 工作流迁到 uv：用 [uv venv](cli:command:venv) 代替 virtualenv，用 `uv pip` 系列命令迁移与锁定依赖，并了解与 pip 的已知差异。

## 前提

- 迁移现场二选一：旧的 virtualenv 还能激活（用它导出依赖清单），或已有 `requirements.in` 之类的顶层声明。
- 已安装 uv 0.12.22。`uv pip` 接口是 pip 的近似替代，不是逐项克隆；越接近常规 pip 用法，行为差异越小。

## 步骤

### 1. 建虚拟环境

```sh
uv venv
uv venv --python 3.11
```

默认在当前目录创建 `.venv`，也可指定路径；请求的 Python 缺失时自动下载。激活不是必需的（后续 uv 命令会自动发现 `.venv`），需要时 `source .venv/bin/activate`。目标路径上已存在 venv 时会移除并新建空环境；非 venv 的非空目录默认报错（TTY 下会询问是否清理），`--clear` 清空后重建，`--force` 允许 `--clear` 清掉非 venv 目录。

### 2. 迁移既有环境（pip freeze → uv pip sync）

```sh
# 旧环境中导出（精确锁定当前实际安装的版本）
pip freeze > requirements.txt

# 新环境中精确复原
uv pip sync requirements.txt
```

[uv pip sync](cli:command:pip/sync) 是精确语义：不在文件里的包会被移除。输入被假定为 compile／导出的产物（包含全部传递依赖）；若缺传递依赖，它们不会被安装——`--strict` 在这种情况下告警。也接受 `pylock.toml`（PEP 751）作为输入。

### 3. 锁定 requirements.in（uv pip compile）

```sh
uv pip compile requirements.in -o requirements.txt
uv pip compile requirements.in -o requirements.txt --upgrade-package <package>
uv pip install -r requirements.txt
```

[uv pip compile](cli:command:pip/compile) 把顶层声明解析为带精确版本的清单。与 pip-tools 的差别：uv 默认**不写输出文件**，必须给 `-o`／`--output-file`。已存在的输出文件中钉住的版本会被尊重，除非 `--upgrade`／`--upgrade-package <package>`。版本约束用 `--constraint constraints.txt`，强制覆盖用 `--override overrides.txt`。装好后用 [uv pip install](cli:command:pip/install) 增量添加（它不删除多余包，要精确回到锁定状态就用 `uv pip sync`）。

### 4. 已知兼容差异

- **不支持 `--user`**：`uv pip install --user` 直接报错（`pip's --user is unsupported (use a virtual environment instead)`），改用虚拟环境；uv 也没有 pip 那种"无写权限时回退 user 安装"的行为。
- **不读 pip 配置**：`pip.conf` 与 `PIP_INDEX_URL` 等被忽略；持久配置用 `uv.toml` 或 `[tool.uv.pip]`，环境变量用 `UV_INDEX_URL` 等 uv 自己的名称。
- **默认要求虚拟环境**：安装类命令按 `VIRTUAL_ENV` → `CONDA_PREFIX` → 当前及父目录 `.venv` 的顺序查找环境，找不到会提示先 `uv venv`；安装到系统 Python 需显式 `--system` 或 `--python /path/to/python`（适合 CI 与容器）。
- **compile 默认值**：默认剥离 extras（`--no-strip-extras` 保留）、默认不向输出写索引 URL（`--emit-index-url` 写入）。
- **默认不编译字节码**：安装不生成 `__pycache__`（`--compile-bytecode` 开启，Docker 镜像建议开启以缩短启动）。
- 构建默认走 PEP 517 隔离；缺少构建依赖时优先升级该包版本，其次用 `--no-build-isolation` 并预装构建依赖。

**风险与边界：** 解析器与 pip 的择优策略不同，合法的解析结果可能不一致；发现差异时通常应收紧自己的版本约束，而不是反复重试。`egg` 类旧格式不受支持。

**未实测声明：** 本工作流依据 uv 0.12.22 固定提交的源码与官方文档快照编写，命令组合未在真实环境实测；`<package>` 与文件名请替换为实际值。
