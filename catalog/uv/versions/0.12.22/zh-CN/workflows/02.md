**适用场景：** 维护一个独立的单文件 Python 脚本：依赖声明内嵌在脚本头部（PEP 723 内联元数据表），不创建项目、不产生 `pyproject.toml`，脚本在独立于项目的隔离环境中执行。

## 前提

- 脚本是一个普通 `.py` 文件；`uv init --script` 时路径为必填（不能像项目那样默认当前目录）。
- 已安装 uv 0.12.22，可联网安装依赖；Python 缺失时 uv 会自动下载。
- 下文以 `example.py` 为文件名，`<package>` 表示任意包名。

## 步骤

### 1. 创建脚本

```sh
uv init --script example.py
```

[uv init](cli:command:init) 加 `--script` 后生成带内联元数据头的独立脚本。默认写入对当前系统 Python 版本的要求；用 `--python 3.12` 指定其他版本要求。再加 `--bare` 时只生成元数据头。该命令与 `--app`、`--lib`、`--package`、`--build-backend` 等项目选项互斥。

### 2. 声明依赖

```sh
uv add --script example.py httpx
```

[uv add](cli:command:add) 的 `--script` 把依赖写进脚本的内联元数据表（遵循 PEP 723）；表不存在时会新建。得到的脚本头部形如（字段以 PEP 723 为准）：

```python
# /// script
# requires-python = ">=3.12"
# dependencies = [
#   "httpx",
# ]
# ///
import httpx

print(httpx.__version__)
```

这个表就是脚本唯一的依赖来源，也可以手工维护（TOML 语法以 `#` 前缀嵌入注释）。注意 `--script` 与 `--dev`、`--optional`、`--group`、`--package` 互斥：脚本依赖没有分组概念。修改元数据表后无需额外"安装"步骤，下次运行时自动生效。

### 3. 运行

```sh
uv run example.py
```

[uv run](cli:command:run) 对 `.py` 结尾的路径（以及 HTTP(S) URL 和 stdin `-`）按脚本处理，等价于 `uv run python example.py`。关键行为：**含内联元数据的脚本自动在隔离的临时环境中安装并运行其依赖**，与项目环境互不影响——即使当前目录位于项目之内。因此上例中的 `httpx` 来自脚本声明，而不是任何 `pyproject.toml`。

两个相邻语义，不要混淆：

- 无内联元数据的 `.py` 文件不会获得隔离环境，而是运行在发现到的项目／虚拟环境中；脚本场景的项目发现从**脚本所在目录**（而非当前工作目录）向上进行。
- `uv run --script example.py` 强制把路径按 PEP 723 脚本解析，用于扩展名不是 `.py` 的脚本文件。

一次性附加依赖用 `--with`：`uv run --with <package> example.py` 会在脚本环境之上叠加临时层，允许与脚本声明冲突。

**执行结果与完成判断：** 脚本正常退出（退出码 0）且输出符合预期即完成；首次运行需要解析并安装依赖，耗时明显长于后续（后续复用缓存环境）。

**风险与边界：** 内联元数据表仅被 uv 等 PEP 723 工具识别，直接用系统 `python example.py` 运行不会安装任何依赖。带元数据的脚本在项目内也不会"继承"项目依赖，混用两种来源时要明确用 `--with`。

**未实测声明：** 本工作流依据 uv 0.12.22 固定提交的源码与官方文档快照编写，命令组合与脚本内容示例未在真实环境实测；`example.py` 与 `<package>` 需替换为实际值。
