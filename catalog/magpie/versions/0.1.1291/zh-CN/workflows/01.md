# 工作流:安装与首次切换模型

从零开始,把某个 agent(以 Codex 为例)从官方模型切换到 DeepSeek。

## 前置条件

- 已安装 magpie 0.1.1291(应用或 `magpie` 命令可用);
- 目标 agent 已安装且至少运行过一次(有配置文件);
- 持有目标厂商的 API key(此处以 DeepSeek 为例)。

## 步骤

1. **确认 agent 被检测到**:[`magpie ls`](cli:command:ls) 应列出 Codex 及其当前模型;未出现说明 agent 尚无配置文件,先运行一次它。
   完成信号:Codex 一行显示当前模型与配置文件路径。
2. **添加 provider**:`magpie provider add deepseek sk-…`(preset 名见 [`magpie presets`](cli:command:presets);重复添加同一家会生成 `deepseek-2` 之类的 id)。
   完成信号:输出 ✓ 与厂商名。
3. **确认可选模型**:[`magpie models codex`](cli:command:models) 列出 Codex 能选的全部 `provider/model`,并解释其余模型为何不可选。
   失败恢复:列表为空时先 `magpie sync` 刷新目录,再 [`magpie provider models deepseek`](cli:command:provider/models) 拉取厂商列表。
4. **切换模型**:[`magpie codex deepseek/deepseek-chat`](cli:command:codex)。magpie 原子改写 Codex 配置,请求改走本地网关 `127.0.0.1:3425`,协议由 OpenAI Responses 转译为 DeepSeek 的 OpenAI Chat。
   完成信号:`magpie codex` 显示模型为 deepseek/deepseek-chat;Codex 内模型名同步变化。
5. **还原**(如需):`magpie codex default` 撤销接管,恢复 Codex 自己的设置。

## 失败与恢复

- 切换后请求报错:先 `magpie provider test deepseek` 验证 key 与连通性;
- 网关未运行:桌面应用/TUI/serve 任一形态在跑即可;服务器场景见 [工作流:无头服务器部署](05.md);
- agent 形式不接受 `-` 开头参数,报错时检查是否把选项写给了 `magpie <agent>`。
