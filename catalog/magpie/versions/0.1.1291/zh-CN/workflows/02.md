# 工作流:添加 provider 与故障转移

添加一个厂商、验证可用、配置配额耗尽时的备用线路。

## 前置条件

- magpie 已运行(网关在跑);
- 目标厂商的 API key;自定义中转站还需其 base URL。

## 步骤

1. **选添加方式**:
   - preset:`magpie provider add deepseek sk-…`(全部预设见 [`magpie presets`](cli:command:presets),含 moonshot-cn、zhipu、minimax-cn 等中国区端点);
   - 自定义 vendor:`magpie provider add myrelay url=https://relay.example/v1 key=…`(k=v 键表见 [`magpie provider add`](cli:command:provider/add) 页)。
2. **验证**:`magpie provider test myrelay`。失败先查 key 与 url,再查本地网络对厂商端点的连通。
3. **挑选暴露的模型**:`magpie provider models myrelay` 拉取列表;`magpie provider models myrelay 'gpt-*'` 之类按需挑选(详细形式见 [`magpie provider models`](cli:command:provider/models))。
4. **设置 fallback**:`magpie provider fallback myrelay deepseek/deepseek-chat openai/gpt-5.5`——myrelay 配额耗尽或宕机时,请求按序转到这些模型;不带参数清除。
5. **(可选)限流与休息策略**:对易限流的厂商设 [`magpie provider rpm`](cli:command:provider/rpm) 与 [`magpie provider quota-rest`](cli:command:provider/quota-rest),避免 key 被长时间拉黑。
6. **核对总览**:[`magpie providers`](cli:command:providers) 显示全部 provider、密钥状态与谁在用它们。

## 完成信号

- `magpie providers` 中新 provider 为 ✓ 状态;
- [`magpie models`](cli:command:models) 里其模型可被 agent 挑选;
- 人为用错 key 重试时,请求自动落到 fallback 模型(可在 `magpie usage --csv` 的 served 列看到实际应答模型)。

## 失败与恢复

- preset 添加报"未认识":确认 preset 拼写与 [`magpie presets`](cli:command:presets) 一致;
- 模型列表为空:厂商不支持列表接口时用 `magpie provider set <id> models=<m1>,<m2>` 手工声明;
- fallback 不生效:fallback 是**该 provider** 的备用,不是全局的;全局多模型冗余用路由组(见 [工作流:路由组实战](04.md))。
