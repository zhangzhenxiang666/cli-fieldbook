# 工作流:无头服务器部署

在没有桌面的服务器或容器里跑 magpie 网关,供本机与其他电脑的 agent 共用。

## 前置条件

- 服务器可安装 magpie(install.sh、`go install` 或 Docker 镜像 `ghcr.io/yetone/magpie`);
- 决定暴露方式:仅本机、局域网、还是 TLS/反向代理对外。

## 步骤

1. **先跑一次同步配置**:无桌面环境首次配置最省力的方式是 [`magpie web`](cli:command:web)——浏览器里打开完整界面:

   ```sh
   magpie web --gateway
   ```

   页面地址默认 `127.0.0.1:3430`,每次运行生成新密钥;SSH 场景做端口转发后在本地浏览器操作。`MAGPIE_WEB_KEY` 固定密钥可保持登入 400 天。
2. **装成系统服务**:[`magpie daemon install`](cli:command:daemon/install) —— launchd(macOS)/systemd --user(Linux),开机自启、停止自动拉起。要连 Web 页面一起服务时加 `--web`;对外监听用 `--lan` 或 `--addr 0.0.0.0:3425`;TLS 用 `--tls-cert`/`--tls-key`(或环境变量 `MAGPIE_TLS_CERT`/`MAGPIE_TLS_KEY`)。
3. **健康检查**:容器 HEALTHCHECK 用 [`magpie healthcheck`](cli:command:healthcheck),退出码 0 即网关应答。
4. **给其他电脑发密钥**:客户端调用共享网关需要 [`gateway-key`](cli:command:gateway-key):

   ```sh
   magpie gateway-key add 笔记本
   ```

   需要限额时:`magpie gateway-key limit <id> month --tokens 50000000 --cost 10`;限模型:`magpie gateway-key models <id> deepseek/*`。
5. **客户端接入**:其他电脑的 agent 照常把 base URL 指向服务器网关地址(如 `http://server:3425`),API key 用网关密钥。
6. **远程管理与诊断**:内存/CPU 异常时 [`magpie heap`](cli:command:heap)、[`magpie cpu`](cli:command:cpu) 采 profile 供报告;更新用 [`magpie update --proxy … --mirror …`](cli:command:update)(受限网络)。

## 完成信号

- `magpie daemon status` 显示服务运行;
- 客户端 agent 请求经服务器网关路由,`magpie usage` 能按 agent 归账;
- 重启服务器后服务自动恢复。

## 失败与恢复

- 端口冲突:3425/3430 被占时用 `--addr`/`MAGPIE_WEB_KEY` 场景对应参数改端口;
- 服务不拉起:`magpie daemon uninstall` 后重新 `install`,已装配置保留;
- Claude Code 本体缺失(纯净容器):`magpie claude-code install` 下载 Anthropic 官方构建并校验清单。
