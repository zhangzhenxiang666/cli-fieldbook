# 工作流:备份与多机同步

两种场景两条路:偶发搬迁用一次性备份,长期多机用 WebDAV/S3/GitHub 同步。

## 前置条件

- 想好一个口令(passphrase):备份与同步文件都用它封存,服务器只见密文;口令丢失无法恢复;
- 同步场景已有 WebDAV 文件夹、S3 兼容桶(AWS/R2/B2/MinIO)或 GitHub 私有仓库之一。

## 场景一:一次性备份与恢复

```sh
magpie backup                      # 全量:providers、密钥、设置、profiles、agent 模型、library
magpie backup --no-keys 搬家.zip   # 不含 API key 的档案
magpie restore 搬家.zip            # 在新机器恢复(--no-agents 跳过 agent 设置)
```

订阅登录凭据不在备份里,恢复后需重新登录各订阅。

## 场景二:多机同步

以 S3 为例(三后端子命令结构一致,差异见 [`magpie s3`](cli:command:s3)、[`magpie webdav`](cli:command:webdav)、[`magpie github`](cli:command:github) 各页):

1. **开启**:

   ```sh
   magpie s3 on s3://my-bucket/magpie access-key-id=… secret-access-key=…
   ```

   R2/MinIO 加 `endpoint=…`,需要时 `path-style=yes`。GitHub 用 `github://owner/repo`;WebDAV 用 `https://dav…/ user=…`。password 与 passphrase 会在终端不回显地询问,也可从 stdin 管道输入(各一行)。
2. **每台机器用同一口令接入**:首次同步时,本机与远端有差异的部分以远端为准,本机被替换的内容保存在同步文件夹旁边并提示。
3. **自动节奏**:`magpie s3 auto 15` 让网关每 15 分钟自己同步(`off` 只手动);手动立即同步用 `magpie s3 now`。
4. **冲突与修复**:
   - `magpie s3 restore`:以本机为准覆盖远端;
   - `magpie s3 undo`:复原上一次 restore;
   - `magpie s3 upload`:强行覆盖远端一个不是备份的文件(旧文件先保留);
   - `magpie s3 dismiss`:清除上次同步提示的替换。
5. **选择性排除**:`set keys=no`(密钥各机自持)、`set agents=no`、`set library=no`;`set usage=yes` 让用量也同步,Usage 页汇总各机器。

## 迁移路线

- WebDAV → S3:`magpie s3 on …` 在 WebDAV 同步开着时直接迁移(桶凭据保留);`magpie webdav on` 单独用则迁回;
- 同步与备份共用封存格式,但同步不是备份的替代:重要节点仍建议偶尔 `magpie backup`。

## 完成信号

- 两台机器各自 `magpie providers`/`magpie ls` 一致,改动在 auto 间隔后互达;
- 断网重连后同步自行恢复,冲突按上述命令可解。

## 失败与恢复

- 口令输错:服务器文件不会被破坏,本机重新 `on` 一次并输入正确口令;
- 权限不足(桶/仓库):先核对 access key 与仓库私有性(GitHub 同步要求私有仓库);
- 想完全停用:`magpie s3 off`(远端文件保留)。
