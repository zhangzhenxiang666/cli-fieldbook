# 工作流:路由组实战

用路由组实现"多模型/多账户当一个挑":顺序兜底、智能轮换、按难度分流三种典型配置。

## 前置条件

- 至少两个可选模型(厂商 key 或订阅,见 [工作流:添加 provider 与故障转移](02.md));
- 理解 [路由组](../concepts/routing-groups.md) 概念(routing 模式、stays 亲和)。

## 场景一:顺序兜底

```sh
magpie group add "Opus anywhere" models=claude/claude-opus-5-5,copilot/claude-opus-5.5 routing=order
```

日常用第一条线路,Claude 订阅耗尽时按序落到 Copilot 的同名模型。随后把 agent 指过去:`magpie claude group/opus-anywhere`。

## 场景二:多订阅智能轮换

```sh
magpie group add "Claude 轮换" models=claude/claude-opus-5-5 routing=smart stays=session
```

组内同一个模型由多个订阅账户应答时,`smart` 每次挑最快恢复额度的账户;`stays=session` 让一个会话粘在同一账户,保住 provider 侧 prompt cache。

## 场景三:按难度分流

```sh
magpie group add Fast models=deepseek/deepseek-v4-flash,glm/glm-5.3-flash
magpie group set fast effort=auto classifier=deepseek/deepseek-v4-flash
```

小模型做分类器,逐轮判断:快问题留在便宜模型,难任务升档(组内 levels 覆盖的档位)。更细的控制用规则:

```sh
magpie group rule add fast …
```

按请求长度、图片、reasoning 要求或 agent 决定先试哪个模型(形式见 [`magpie group rule`](cli:command:group/rule) 页)。

## 核对与调整

- [`magpie groups`](cli:command:groups):你的组在前,magpie 自动发现的组在后;
- [`magpie group <id>`](cli:command:group):看组的模型与当前路由;
- 增删成员不重建:`magpie group set <id> models+=<m>` / `models-=<m>`;
- 改 id:`magpie group set <id> id=新id`——引用旧 id 的 agent 需要重新设置。

## 完成信号

- agent 的模型显示为 `group/<id>`;
- [`magpie models <agent>`](cli:command:models) 中组可被挑选;
- 单个成员故障/耗尽时请求仍成功,`magpie usage --csv` 的 served 列显示实际应答者。

## 失败与恢复

- 删错了自动发现的组:`magpie group restore <id>` 找回;
- 想暂时不用某模型:`magpie model disable <model>` 全局禁用,比改组更彻底;
- 组嵌套层数过深难以推断路由时,`magpie group <id>` 逐层展开核对。
