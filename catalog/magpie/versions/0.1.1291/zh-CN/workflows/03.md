# 工作流:订阅账户管理与故障转移

把已有订阅(Claude、ChatGPT、Copilot、Gemini 等)交给 magpie 统一调度:多账户并存、配额轮转、耗尽自动切换。

## 前置条件

- 对应 agent(如 Claude Code、Codex)已登录订阅;
- 理解 [订阅账户](../concepts/accounts.md) 概念:订阅会作为 provider 服务其他 agent。

## 步骤

1. **查看已发现的订阅**:[`magpie accounts`](cli:command:accounts) 列出每个订阅的额度使用与重置窗口。自动发现默认开;未发现时检查 `magpie accounts discovery` 状态。
2. **补充账户**:
   - 再登入一个:`magpie accounts add claude`;
   - 从其他工具导入:`magpie accounts import codex ~/somewhere/auth.json`(来源工具会被登出,确认后再做);
   - 给账户起名便于辨认:`magpie accounts alias claude me@example.com 主力号`([`magpie accounts alias`](cli:command:accounts/alias))。
3. **设置份额与并发**(多账户避免互踩):
   - `magpie provider account-cap claude 主力号 70`——单窗口最多用到 70%,到线即视为耗尽、路由换号;
   - `magpie provider account-concurrency claude 主力号 4`——同时最多 4 个请求([`magpie provider`](cli:command:provider) 子命令表)。
4. **组合成路由组实现自动切换**:`magpie group add "Claude 轮换" models=claude/claude-opus-5-5 routing=smart stays=session`,agent 挑 `group/claude-轮换`;smart 优先发给最快恢复额度的账户,会话亲和保住 prompt cache(详见 [工作流:路由组实战](04.md))。
5. **等待额度恢复**(脚本/CI 场景):[`magpie quota wait claude`](cli:command:quota/wait) 阻塞到任一账户有额度,`--timeout` 限定等待上限。

## 完成信号

- `magpie accounts` 各账户用量与窗口正常滚动;
- 一个账户耗尽后,新请求自动落到组内下一个账户,会话内粘住同一账户。

## 失败与恢复

- 登录过期:ChatGPT 类用 [`magpie accounts refresh`](cli:command:accounts/refresh) 立即续期(网关平时每日自动做);
- 不想让请求过网关(隐私/延迟考虑):`magpie accounts switch-only codex on` 只切换 Codex 自身登录、直连 OpenAI;
- 介意凭据被读取:`magpie accounts discovery off` 关闭自动发现,改手动 add。
