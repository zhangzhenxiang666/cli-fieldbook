目标：在一台新机器上完成 coolify CLI 的首次配置，并确认它能连上你的 Coolify 实例。本工作流未实测，示例输出为依据源码的预期形式。

## 前置条件

- 已安装 coolify CLI 1.8.0（`coolify version` 确认）；
- 拥有 Coolify 控制台访问权，可在「Security → API Tokens」创建令牌；
- 实例 URL 可从本机访问（如 `https://coolify.example.com`）。

## 步骤

### 1. 登记上下文

```sh
coolify context add -d prod https://coolify.example.com <你的令牌>
```

`-d` 同时把它设为默认上下文；这是首个上下文，即使不加 `-d` 也会成为默认。令牌写入本机配置文件，命令输出不回显令牌。

### 2. 验证连通与认证

```sh
coolify context verify
```

预期输出（形式）：

```text
✓ Connection successful
✓ Authentication valid
✓ Coolify version: v4.x.x
```

该命令向实例发起一次版本查询，等于同时检查了 URL 与令牌。失败时先区分是网络问题（连接超时）还是令牌问题（401）。

### 3. 多实例时切换默认上下文

```sh
coolify context add staging https://staging.example.com <令牌>
coolify context use prod
```

`context use` 的语义是把指定上下文设为默认。之后所有命令默认作用于 `prod`，单次调用也可用 `--context staging` 临时切换。

### 4. 核对配置

```sh
coolify context list
```

确认两个上下文都在列，且默认项正确。v1.8.0 起该输出不包含令牌字段。

## 完成标志

`context verify` 输出三项确认即完成。后续任何命令报 401 时，回到第 2 步排查。
