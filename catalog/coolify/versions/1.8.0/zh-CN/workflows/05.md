目标：用官方模板快速起一个 n8n 服务，并在异常时定位问题。本工作流未实测，示例输出为预期形式。

## 前置条件

- `--server-uuid`、`--project-uuid` 已知，环境名称确定；
- 不确定要装什么模板时，先看清单。

## 步骤

### 1. 查看可用类型

```sh
coolify service create --list-types
```

输出当前服务端支持的模板类型列表（该清单由服务端版本决定）。

### 2. 创建并立即部署

```sh
coolify service create n8n \
  --server-uuid <uuid> --project-uuid <uuid> --environment-name production \
  --name my-n8n --instant-deploy
```

模板包含多个子应用时（如 `wordpress-with-mysql`）需再指定 `--sub-service-name` 指明要操作的应用。

### 3. 读取服务 UUID

```sh
coolify service list --format json | jq -r '.[] | select(.name=="my-n8n") | .uuid'
```

### 4. 排障路径

按以下顺序排查，不要一上来就重启：

```sh
coolify service logs <service-uuid> --sub-service-name <子服务名>
```

日志最先暴露启动失败的原因（缺环境变量、端口冲突等）。环境变量问题就地修正：

```sh
coolify service env sync <service-uuid> --file .env.n8n
```

确认配置修正后再整体重启：

```sh
coolify service restart <service-uuid>
```

restart 会重启服务的全部容器；重启后回到 `logs` 确认状态。

## 完成标志

`service get <service-uuid>` 显示运行中，且日志无持续报错。
