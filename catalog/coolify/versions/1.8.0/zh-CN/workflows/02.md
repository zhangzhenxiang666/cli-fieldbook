目标：把一个公共 Git 仓库部署成 Coolify 应用，并跟踪到部署完成。本工作流未实测，示例输出为预期形式。

## 前置条件

- 上下文已配置且 `context verify` 通过；
- 已知目标 `--server-uuid` 与 `--project-uuid`（可分别用 `coolify server list --format json` 与 `coolify project list --format json` 查询）；
- 目标环境名称确定（如 `production`）。

## 步骤

### 1. 创建应用

```sh
coolify app create public \
  --server-uuid <uuid> --project-uuid <uuid> --environment-name production \
  --git-repository "https://github.com/user/repo" --git-branch main \
  --build-pack nixpacks --ports-exposes 3000
```

`--build-pack` 与 `--ports-exposes` 是必需参数；`--domains` 与 `--compose-domain` 互斥，绑定域名只取其一。

### 2. 触发部署

创建命令不加 `--instant-deploy` 时只建不部署。之后按 UUID 部署：

```sh
coolify app list --format json | jq -r '.[] | select(.name=="repo") | .uuid'
coolify deploy uuid <app-uuid>
```

返回的是「部署请求已被接受」，部署在服务端异步进行；用 `deploy get <部署uuid>` 或 `coolify deploy list` 跟踪进度。

### 3. 观察构建日志

```sh
coolify app logs <app-uuid> --follow
```

`--follow` 持续输出新日志；构建失败时这里最先出现原因。

### 4. 确认完成

`deploy list` 中不再出现该应用、且 `app get <app-uuid>` 状态为运行中，即部署完成。超时未完成不等于失败——去服务端部署详情里看具体阶段。

## 失败恢复

- 构建失败：修正仓库或构建参数后重新 `deploy uuid`；
- 选错构建方式：应用层参数在服务端调整，CLI 1.8.0 的 `app update` 未收录本手册，可直接在控制台修改后重新部署。
