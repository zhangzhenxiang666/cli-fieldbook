目标：新建一个 PostgreSQL 数据库，配置定时备份并手动触发一次验证。本工作流未实测，示例输出为预期形式。

## 前置条件

- `--server-uuid`、`--project-uuid` 已知，环境名称确定；
- 若要把备份上传 S3，已有可用的 S3 存储配置（其 UUID 需从服务端获取；`s3` 命令组未收录本手册）。

## 步骤

### 1. 创建数据库

```sh
coolify database create postgresql \
  --server-uuid <uuid> --project-uuid <uuid> --environment-name production \
  --postgres-db appdb --postgres-user app --postgres-password <口令> \
  --limits-cpus '0.5' --limits-memory '512m'
```

每个数据库类型有对应的旗标组（`--mysql-*`、`--mongo-*`、`--redis-password` 等）；`--is-public` 开放公网访问，默认关闭。

### 2. 配置定时备份

```sh
coolify database backup create <database-uuid> \
  --frequency '0 3 * * *' \
  --retention-days-locally 7 --retention-days-s3 30 \
  --retention-max-storage-locally 5 --retention-max-storage-s3 20 \
  --save-s3 --s3-storage-uuid <uuid>
```

注意 v1.8.0 的破坏性变更：`--retention-max-storage-locally` 与 `--retention-max-storage-s3` 现在接受**数值型 GB** 存储上限（旧版本的写法不再适用）。上面示例含义：本地最多留 7 天且不超过 5 GB，S3 最多 30 天且不超过 20 GB，每日 03:00 执行。

### 3. 手动触发一次验证

```sh
coolify database backup trigger <database-uuid> <backup-uuid>
```

`backup-uuid` 从 `coolify database backup list <database-uuid>` 获得。触发成功只表示备份任务已开始；执行结果看下一步。

### 4. 查看执行记录

```sh
coolify database backup executions <database-uuid> <backup-uuid>
```

最新一条记录为成功状态即备份链路可用。失败时常见原因是 S3 凭据或网络目标问题，修正后重新触发即可——trigger 无副作用积累，可安全重试。

## 完成标志

执行记录中出现一次成功备份，且保留策略与预期一致。
