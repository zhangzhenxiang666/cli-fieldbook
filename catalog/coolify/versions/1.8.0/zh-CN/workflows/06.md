目标：在 CI 流水线中以机器可读方式触发部署并跟踪结果，失败时干净地取消。本工作流未实测，示例输出为预期形式。

## 前置条件

- CI 环境中已注入实例 URL 与 API 令牌（建议以 secret 形式提供）；
- 资源在 Coolify 中的名称在流水线中已知且唯一。

## 步骤

### 1. 前置校验

```sh
coolify --token "$COOLIFY_TOKEN" --context prod context verify
```

`--token` 临时覆盖认证，不为流水线单独建上下文。此步失败应直接终止作业，避免后续误报。

### 2. 按名称触发部署

```sh
coolify deploy name myapp --format json > deploy.json
uuid=$(jq -r '.uuid' deploy.json)
```

按名称寻址让流水线免于维护 UUID。注意：返回 JSON 表示**部署请求已被接受**，不等于部署完成。

### 3. 轮询部署状态

```sh
coolify deploy get "$uuid" --format json | jq -r '.status'
```

以固定间隔轮询直至状态为终态（成功或失败）。设置整体超时时间，超时只说明尚未完成，需结合状态字段判断，不要默认失败即放弃。

### 4. 失败或超时的处置

确认要中止时：

```sh
coolify deploy cancel "$uuid" --force
```

`--force` 跳过交互确认（CI 中必须）；该操作要求服务端不低于 `4.0.0-beta.436`。取消后排查原因，修复合再从第 2 步重来——deploy 是幂等的部署触发，不会因重试产生半成品资源。

## 完成标志

轮询到成功状态；流水线日志中留有每次部署的 UUID 便于回溯。
