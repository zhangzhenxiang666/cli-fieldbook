目标：把本地维护的 `.env` 文件应用到应用的环境变量，并保证构建期/运行期语义正确。本工作流未实测，示例输出为预期形式。

## 前置条件

- 应用已创建，UUID 已知；
- 本地已有 `.env.production` 文件（`KEY=value` 格式）；
- 明确哪些变量需要构建期可用（如 `NODE_ENV`）、哪些只应运行期存在（如数据库口令）。

## 步骤

### 1. 同步前先看现状

```sh
coolify app env list <app-uuid>
```

默认只列非预览变量。记下已有的键，判断 sync 后哪些会被更新。

### 2. 执行同步

```sh
coolify app env sync <app-uuid> --file .env.production
```

sync 的语义是**更新已有键、创建缺失键**，不删除服务端多出的变量——本地删掉的键不会自动在服务端消失。预期输出会报告解析到的变量数量与同步进度。

需要整批控制作用域时：

```sh
coolify app env sync <app-uuid> --file .env.production --runtime --build-time=false
```

注意：v1.8.0 修复了 `is_buildtime` 载荷问题（上游 #84）；旧版本上构建期属性可能不生效，升级后再依赖该语义。

### 3. 逐个修正特殊变量

个别变量需要与整批不同的属性（如某个密钥设为字面量）：

```sh
coolify app env update <app-uuid> <env-uuid-或-key> \
  --value 'v=${literal}' --is-literal
```

`update` 也支持用 `--key` 重命名。

### 4. 验证并重新部署

`app env list <app-uuid>` 核对结果后，环境变量变更要经下一次部署才进入运行环境：`coolify deploy uuid <app-uuid>`。

## 完成标志

`env list` 与 `.env` 文件一致（多余键除外），且最后一次部署成功。
