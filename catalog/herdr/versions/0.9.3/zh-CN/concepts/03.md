---
title: 3. Agent 状态的两套集合
---

| 值         | 阅读状态时的含义        | `agent wait` / `prompt --until` | `pane report-agent --state` |
| --------- | --------------- | ------------------------------- | --------------------------- |
| `idle`    | 当前不在工作、可等待下一步输入 | 接受                              | 接受                          |
| `working` | 正在工作            | 接受                              | 接受                          |
| `blocked` | 等待人工输入、确认或其他介入  | 接受                              | 接受                          |
| `done`    | 对外呈现的完成状态       | 接受                              | **不接受**                     |
| `unknown` | 无法可靠识别当前状态      | 接受，但须显式指定才进入默认等待以外的匹配           | 接受                          |

`unknown` 不是 `idle`，`blocked` 也不是业务成功。`agent wait` 默认的匹配集合是 **idle / done / blocked**。`--until` 可重复，关系是**或**，不是先后顺序。

`agent wait` 等待的是状态条件，不是新任务。调用瞬间已匹配便可能立即返回。`agent prompt --wait` 加入了提交后的启动观察，但仍不追踪请求对应的 turn：原本正在工作的 Agent 可能以旧任务完成状态满足等待。因此，业务自动化必须核验 Agent 输出，不能把命令退出 0 直接等同于“这次需求已完成”。

当 prompt 被接受且开始于非 working 状态，5000ms 内没有观察到 working 或 blocked，会报 `agent_prompt_stalled`；更早到期的调用方 timeout 则先返回 timeout。两者都不构成安全重复提交的依据。[S01](https://github.com/herdrdev/herdr/blob/7b116c05bfda646af39d2524c54e70c751f57ee8/src/cli/spec.rs#L6-L966)[S05](https://github.com/herdrdev/herdr/blob/7b116c05bfda646af39d2524c54e70c751f57ee8/src/cli/agent.rs)
