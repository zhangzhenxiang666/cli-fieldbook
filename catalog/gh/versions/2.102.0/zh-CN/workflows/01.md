**适用场景：** 在一台新机器上让 gh 与 git 共用同一份 GitHub 凭据：完成登录（浏览器或令牌两种方式）、选定 git 操作协议、验证认证状态、把 gh 配置为 git 凭据助手，并处理脚本取令牌与多账号两个常见后续问题。

## 前提

- 已安装 gh 2.102.0，尚未认证：此时多数命令会提示先运行 `gh auth login` 并以退出码 `4` 结束（见[退出代码](../reference/exit-codes.md)）。
- 浏览器流程需要能打开浏览器；令牌流程需要一把 classic 个人访问令牌，最小 scope 为 `repo`、`read:org` 与 `gist`（细粒度令牌建议改用 `GH_TOKEN` 环境变量，见[环境变量](../reference/environment.md)）。
- 下文 `<hostname>` 表示 GitHub 主机名（默认 `github.com`），`<user>` 表示账号名。

## 步骤

### 1. 浏览器流程登录

```sh
gh auth login
```

[gh auth login](cli:command:auth/login) 默认走交互式流程，依次询问（提示文本为源码原文）：

1. `Where do you use GitHub?`——选 `GitHub.com` 或 `Other`（后者要求输入主机名）。
2. `What is your preferred protocol for Git operations on this host?`——`HTTPS`（默认）或 `SSH`；选择即时生效于该主机的 git 协议配置，且对该主机上的所有账号生效。
3. 选 `HTTPS` 时追问 `Authenticate Git with your GitHub credentials?`——同意后 gh 把自己注册为该主机的 git 凭据助手，并为此额外申请 `workflow` scope（保证包含工作流文件改动的 push 能通过认证）。
4. 选 `SSH` 时检测本地公钥并提示上传；找不到公钥且系统有 ssh-keygen 时询问是否生成 `id_ed25519`，上传会追加 `admin:public_key` scope。`--skip-ssh-key` 可跳过这一段。
5. `How would you like to authenticate GitHub CLI?`——选 `Login with a web browser`，显示一次性代码并提示按 Enter 打开浏览器，在网页输入代码完成授权。

完成后输出（写入 stderr，各行均出自源码）：

```console
✓ Authentication complete.
- gh config set -h github.com git_protocol https
✓ Configured git protocol
✓ Logged in as <user>
```

第二行是 gh 把所选协议持久化的等价命令回显，选 `SSH` 时显示为 `git_protocol ssh`。令牌存入系统凭据管理器；找不到可用凭据管理器时回退为明文文件并给出警告。非交互终端（如无法弹窗的环境）改用 `--web` 时，gh 会打印 `Open this URL: <url>` 让你手动在别处打开浏览器。

### 2. 令牌流程登录

```sh
gh auth login --with-token < mytoken.txt
```

`--with-token` 从标准输入读入令牌，不产生任何提示，适合无头环境。gh 会先经 API 校验令牌具备最小 scope，不满足时报错且不写入任何配置。与浏览器流程的两点差异：

- 不询问 git 凭据助手，也不提示选择 git 协议；需要时以 `--git-protocol` 与本命令同给，或事后用 `gh auth setup-git`（下一步）与 [`gh config set`](cli:command:config/set) 补上。
- `--with-token` 与 `--web`、`--scopes` 互斥，不能同时给出。

若环境中已设置 `GH_TOKEN` 等变量，gh 会优先使用环境变量令牌，登录时会提示先清除环境变量中的值，否则无法把凭据写入存储。

### 3. 验证：gh auth status

```sh
gh auth status
```

[gh auth status](cli:command:auth/status) 逐主机检测所有已知账号。单账号、凭据存于系统凭据管理器时的输出形态（打码规则：保留令牌前缀，其余字符以 `*` 代替，长度与真实令牌一致）：

```console
github.com
  ✓ Logged in to github.com account <user> (keyring)
  - Active account: true
  - Git operations protocol: https
  - Token: gho_****************************************
  - Token scopes: 'gist', 'read:org', 'repo'
```

`Token scopes` 一行的取值与顺序来自服务端响应；仅 `ghp_`、`gho_` 开头的令牌会检查 scope，缺失时提示用 `gh auth refresh -h <hostname>` 补齐。存在认证问题时输出转至 stderr 并以退出码 `1` 结束；`--json` 模式则始终以 `0` 结束，便于脚本判断。`--show-token` 以明文显示令牌，注意终端历史。

### 4. 配置 git 凭据助手

```sh
gh auth setup-git
```

[gh auth setup-git](cli:command:auth/setup-git) 把 `credential.<hostname>.helper` 写入 git 全局配置：先以空值切断该主机既有的凭据助手链，再追加 `!<gh 可执行文件路径> auth git-credential`，使 git 的 https 推拉操作复用 gh 存储的令牌。第 1 步选 `HTTPS` 且同意配置的用户已完成此设置；本命令用于令牌流程补配、追加新主机，或事后重配。

默认为所有已认证主机配置；`--hostname <hostname>` 只配置单台主机，该主机未认证时报错，`--force` 可与 `--hostname` 同用跳过该检查。实际应答凭据请求的是 [`gh auth git-credential`](cli:command:auth/git-credential)，本命令只写配置条目。

### 5. 调整 git 协议

```sh
gh config set git_protocol ssh --host github.com
```

[gh config set](cli:command:config/set) 把 `git_protocol` 键写入配置文件：合法取值为 `ssh` 与 `https`，默认 `https`；`--host` 按主机设置，省略时写入全局配置。该键决定 [`gh repo clone`](cli:command:repo/clone) 等命令构造 URL 时使用的协议；git 推拉本身的协议还取决于远端 URL 与凭据助手配置。取值不在合法集合内会报错并列出合法值，不会写入。

### 6. 脚本取令牌与多账号

脚本中需要令牌（例如为其它工具提供认证）时：

```sh
export GH_TOKEN="$(gh auth token)"
```

[gh auth token](cli:command:auth/token) 按与 gh 相同的顺序查找令牌：先环境变量，再本地配置文件，最后系统凭据管理器；默认输出当前主机活动账号的令牌，`--hostname` 与 `--user` 可指定。令牌以明文输出，注意终端历史与日志；自动化场景更稳妥的做法是直接使用 `GH_TOKEN` 环境变量。

一台主机登录多个账号时，重复运行 `gh auth login --hostname <hostname>` 即可追加账号；[gh auth status](cli:command:auth/status) 会标出每台主机上的活动账号。切换活动账号用 [gh auth switch](cli:command:auth/switch)：该主机只有两个账号时自动切到非活动账号，更多账号需以 `--user` 指定。切换只改变后续命令以哪个账号的身份执行，不删除其它账号的已存凭据；环境变量中已有令牌时命令拒绝切换。

**状态变化一览：**

| 命令 | gh 配置文件 | git 全局配置 | 令牌存储 |
| --- | --- | --- | --- |
| `gh auth login`（浏览器） | 写入主机段：账号、令牌引用、`git_protocol` | 选 HTTPS 并同意时写 `credential.<host>.helper` | 写入凭据管理器（回退明文） |
| `gh auth login --with-token` | 写入主机段：账号、令牌引用、显式给出的 `git_protocol` | 不修改 | 按存储可用性写入 |
| `gh auth setup-git` | 不修改 | 写 `credential.<host>.helper` | 不修改 |
| `gh config set` | 写入指定键 | 不修改 | 不修改 |
| `gh auth switch` | 修改主机段活动账号 | 不修改 | 不修改 |
| `gh auth token` | 只读 | 只读 | 只读 |

**风险与边界：** `gh auth setup-git` 修改的是 git 全局配置，会切断该主机既有的凭据助手链；机器上另有凭据助手（如 osxkeychain 独立使用）时需确认影响范围。令牌流程不做 scope 追加，后续需要 `workflow`、`project` 等 scope 时须重新走 `gh auth refresh -s <scope>`。浏览器流程在非交互终端不会自动打开浏览器，需自行处理打印出的 URL。回退为明文存储时凭据写在磁盘文件中，`gh auth status` 会显示其位置。
