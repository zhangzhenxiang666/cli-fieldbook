**适用场景：** 围绕仓库的建立与获取：从零创建远程仓库、把既有本地目录挂到新远程仓库、克隆仓库、复刻他人仓库并在本地同时保留上游，最后处理多远端下的默认仓库歧义与网页跳转。

## 前提

- 已安装 gh 2.102.0 并完成认证（流程见[工作流 01](01.md)）。
- 本地已安装 git：`gh repo clone` 与 `gh repo fork --clone` 都是调用 `git clone` 完成实际抓取。
- 下文 `<owner>/<repo>` 表示仓库全名，`<name>` 表示仓库名；省略 `OWNER/` 前缀时仓库默认归属当前认证用户。

## 步骤

### 1. 创建远程仓库

```sh
gh repo create <name> --private --clone
```

[gh repo create](cli:command:repo/create) 给出参数或旗标即为非交互模式，此时 `--public`、`--private`、`--internal` 三者必须恰好给一个，否则报错；`--clone` 把新仓库克隆到当前目录。名称中带 `OWNER/` 前缀时仓库归属该所有者（如组织）。新仓库的默认分支遵循账户的仓库默认分支设置。

不带任何参数与旗标运行 `gh repo create` 则进入交互流程，可选择从零创建、以模板仓库创建或推送既有本地仓库三种路径。

### 2. 把现有本地目录挂到远程仓库

```sh
gh repo create <owner>/<repo> --private --source=. --remote=origin --push
```

`--source` 指定本地仓库路径，远程仓库名默认取源目录名，这里显式给出全名。配套旗标：

- `--remote` 指定添加的远端名称，省略时默认 `origin`；`--push` 把本地提交推送到新仓库，要求本地已有提交（源为裸仓库时改为 `push --mirror` 镜像全部 ref）。
- `--remote` 与 `--push` 只能与 `--source` 同用；`--source` 不能与 `--clone`、`--template`、`--license`、`--gitignore` 组合。

这一步只添加远端并推送，不改动本地提交历史；工作目录、当前分支都保持原样。

### 3. 克隆仓库

```sh
gh repo clone <owner>/<repo>
gh repo clone <owner>/<repo> <directory> -- --depth=1
```

[gh repo clone](cli:command:repo/clone) 解析仓库参数后调用 `git clone`。参数不含协议方案时，克隆协议取自 `git_protocol` 配置；以 URL 形式给出协议方案时按指定协议克隆。`--` 之后的旗标原样透传给 `git clone`，直接把 `git clone` 的旗标写给 `gh repo clone` 本身会报错。

克隆目标是复刻时，gh 额外把父仓库添加为名为 `upstream` 的 git 远端（`--upstream-remote-name` 改名，支持 `@owner` 值；`--no-upstream` 跳过），并把它设为默认仓库——这正是第 5 步同步上游的基础。

### 4. 复刻他人仓库

```sh
gh repo fork <owner>/<repo> --clone
```

在仓库外运行（给出仓库参数）时，[gh repo fork](cli:command:repo/fork) 创建复刻并可配合 `--clone` 把复刻克隆到当前目录；克隆完成后同样把父仓库加为 `upstream` 远端并设为默认仓库。复刻已存在时不报错，只提示已存在。

在本地仓库内不带参数运行时行为不同：创建复刻后把它设为 `origin` 远端，既有的 `origin` 改名为 `upstream`，并把 `upstream` 设为默认仓库。`--default-branch-only` 让复刻只包含源仓库的默认分支。

### 5. 同步复刻的上游

复刻落后于上游时，在本地复刻目录内：

```sh
gh repo sync
```

[gh repo sync](cli:command:repo/sync) 省略参数时以本地仓库为目标，源仓库默认为目标仓库的父仓库：从对应远端 fetch 后把源仓库默认分支（`--branch` 可指定）快进合并到本地。三条约束：源仓库必须能对应到本地的一个 git 远端；待同步分支恰为当前分支且其上有未提交或未跟踪改动时拒绝执行（提示先 `git stash`）；本地分支与源已分叉时报错并提示用 `--force` 硬重置——`--force` 会丢弃本地分叉提交，确认无用后再用。

要把上游变更同步到 GitHub 上的复刻仓库本身，改为给出目标仓库：`gh repo sync <owner>/<repo>`，走 merge-upstream API，失败时回退到 references API。它同样只做 fast-forward，除非 `--force`。

### 6. 消除默认仓库歧义并打开网页

本地同时有 `origin`（复刻）与 `upstream`（上游）两个远端时，gh 需要知道 pr、issue 等命令以哪个仓库为目标：

```sh
gh repo set-default
gh repo set-default --view
gh browse
```

[gh repo set-default](cli:command:repo/set-default) 不带参数时从本地远端解析出的仓库网络中交互选择，只解析到一个时直接选用；参数也可以直接给 `OWNER/REPO` 或 git 远端名。默认仓库决定查看与创建拉取请求、议题、release 及操作 GitHub Actions 时的目标仓库。`--view` 查看当前值，`--unset` 取消。

[gh browse](cli:command:browse) 在浏览器打开当前仓库页面：位置参数三选一——数字（议题或拉取请求）、路径（可带 `:行号` 选区）、提交 SHA；`--settings`、`--releases`、`--wiki`、`--actions`、`--projects` 打开对应页面（与位置参数互斥），`--no-browser` 只打印 URL 便于脚本。

**状态变化一览：**

| 命令 | GitHub 上的仓库 | 本地目录／git 配置 | gh 默认仓库设置 |
| --- | --- | --- | --- |
| `gh repo create <name>` | 创建远程仓库 | 加 `--clone` 时新建目录 | 不涉及 |
| `gh repo create --source` | 创建远程仓库 | 添加远端；`--push` 推送提交 | 不涉及 |
| `gh repo clone` | 不修改 | 新建目录；克隆复刻时添加 `upstream` 远端 | 克隆复刻时设上游为默认 |
| `gh repo fork`（仓库内） | 创建复刻 | `origin` 改名 `upstream`，复刻设为 `origin` | 设 `upstream` 为默认 |
| `gh repo fork <repo> --clone` | 创建复刻 | 新建目录，添加 `upstream` 远端 | 设 `upstream` 为默认 |
| `gh repo sync` | 不修改（带目标参数时更新远端复刻） | 快进或重置本地分支 | 不涉及 |
| `gh repo set-default` | 不修改 | 不修改 | 写入或清除默认 |

**风险与边界：** `gh repo create` 非交互模式缺可见性旗标直接报错，不会按隐藏默认值创建。`gh repo sync --force` 与远端模式的 `--force` 都是丢弃式操作：本地分叉提交或复刻上的独有提交会丢失，作用范围是单个分支。`gh repo fork` 在仓库内运行时会把既有 `origin` 改名为 `upstream`，依赖 `origin` 名称的脚本会受影响；显式给 `--remote-name` 可避免改名，但该名称已存在时报错。`gh repo set-default` 给出的仓库必须对应本地某个 git 远端。
