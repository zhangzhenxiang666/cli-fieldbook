**适用场景：** 面向写脚本与报表的人：当现成子命令不覆盖所需字段、或要批量拉取数据时，用 [gh api](cli:command:api) 直接访问 REST 与 GraphQL，用 [gh search](cli:command:search) 系列定位对象，再把两者接成管道；最后处理脚本中的认证令牌。

## 前提

- 已安装 gh 2.102.0，并已完成 [gh auth login](cli:command:auth/login) 认证；脚本环境建议用 `GH_TOKEN` 提供令牌（见步骤 7）。
- 下文 `<owner>/<repo>` 表示仓库；`--jq` 表达式与 Go 模板按需替换。REST 响应的字段名以 GitHub REST API 文档为准，gh 只负责发起请求与加工输出。
- 本文示例多为说明性管道，字段与占位符需按真实数据核对。

## 步骤

### 1. 基本请求与占位符

```sh
gh api repos/{owner}/{repo}/issues --jq '.[].title'
gh api -X GET search/issues -f q='repo:<owner>/<repo> is:open bug'
```

[gh api](cli:command:api) 的 `<endpoint>` 是 REST API 路径，或字面量 `graphql`。端点中的 `{owner}`、`{repo}`、`{branch}` 占位符会被当前目录所在仓库（或 `GH_REPO` 指定仓库）的值替换；仅通过 `GH_REPO` 指定仓库时 `{branch}` 无法确定取值，使用会报错。没有参数时默认 `GET`，添加了任何参数后自动切 `POST`：`-f`/`--raw-field` 添加字符串参数，要作为 `GET` 查询串发送须显式 `--method GET`（如第二条示例）。`-F`/`--field` 做类型推断（`true`、`false`、`null`、整数），值以 `@` 开头时从文件读取（`@-` 为标准输入）；`--input` 从文件读整个请求体，此时字段旗标改加到查询串上。

### 2. 分页拉取

```sh
gh api repos/{owner}/{repo}/issues --paginate --jq '.[].title'
gh api graphql --paginate -f query='
  query($endCursor: String) {
    viewer {
      repositories(first: 100, after: $endCursor) {
        nodes { nameWithOwner }
        pageInfo { hasNextPage endCursor }
      }
    }
  }
'
```

`--paginate` 依次请求所有页直到没有下一页，仅支持 `GET` 请求与 `graphql` 端点，且不能与 `--input` 同用。REST 分页下 `--jq` 逐页应用于每页响应的数组，上面的组合即可遍历全部议题标题。GraphQL 分页要求原始查询声明 `$endCursor: String` 变量，并从集合取得 `pageInfo { hasNextPage endCursor }` 字段组。默认每页是独立的 JSON 数组或对象；加 `--slurp` 把所有页包进一个外层 JSON 数组——它必须与 `--paginate` 同用，且不能与 `--jq` 或 `--template` 同用，跨页聚合时用 `--slurp` 配合管道外部的 jq 处理。

### 3. 输出加工：--jq 与 --template

```sh
gh api repos/{owner}/{repo}/issues --jq '.[].title'
gh search prs --repo <owner>/<repo> --state open --json number,title,updatedAt --template \
  '{{range .}}{{tablerow (printf "#%v" .number) .title (timeago .updatedAt)}}{{end}}'
```

`--jq` 用 jq 查询语法筛选或重组 JSON，系统无需安装 jq，连接终端时自动美化输出；`--template` 用 Go 模板渲染，可用 `tablerow`、`tablerender`、`timeago`、`timefmt`、`pluck`、`join`、`truncate`、`hyperlink` 等附加函数，见[JSON 输出与格式化](../reference/formatting.md)。`gh search` 系列 `--json` 导出的是结果数组，`--template` 用 `{{range .}}` 遍历渲染成对齐表格。在 `gh api` 中 `--template`、`--jq`、`--silent`、`--verbose` 四者至多选一；其他命令里 `--jq`/`--template` 都须与 `--json` 同用。

### 4. GraphQL 查询

```sh
gh api graphql -F owner='{owner}' -F name='{repo}' -f query='
  query($name: String!, $owner: String!) {
    repository(owner: $owner, name: $name) {
      releases(last: 3) {
        nodes { tagName }
      }
    }
  }
'
```

`graphql` 端点下，除 `query` 与 `operationName` 之外的字段都解释为 GraphQL 变量：`-f query=...` 传查询文本，`-F`/`-f` 传变量值（`-F` 保留 `{owner}`/`{repo}` 占位符与类型推断能力）。GraphQL 端点同样适用步骤 2 的分页规则。

### 5. 搜索入口：gh search

```sh
gh search issues --repo <owner>/<repo> --label bug --state open --limit 50
gh search prs --review-requested=@me --state=open
gh search repos --language=go --sort=stars --limit 10
gh search code --repo <owner>/<repo> 'func Decode' --extension=go
```

[gh search issues](cli:command:search/issues)、[gh search prs](cli:command:search/prs)、[gh search repos](cli:command:search/repos)、[gh search code](cli:command:search/code) 共享一套构造方式：关键词与搜索语法限定符、限定符旗标，或两者组合。`--limit` 默认 30、取值 1 到 1000；`--json` 导出结构化结果并配 `--jq`/`--template`。注意：搜索结果为空且未用 `--json` 导出时，命令以失败结束——脚本里应把"无结果"当作正常分支处理。查询包含以连字符开头的限定符（如 `-label:bug`）时，用 `--` 终止选项解析（`gh search prs -- -label:bug`）。差异点：`gh search issues` 默认不含拉取请求（`--include-prs` 纳入），`--search-type semantic`/`hybrid` 提供语义检索但只返回一页且不能与 `--sort`/`--order` 同用；`gh search prs` 另有 `--base`、`--head`、`--draft`、`--merged`、`--review`、`--review-requested`、`--checks` 等拉取请求专属限定符；`gh search code` 走旧版代码搜索引擎，结果可能与网页端新版搜索不一致。

### 6. 组合管道

```sh
# search 定位，再逐条经 REST 取详情
gh search issues --repo <owner>/<repo> --label bug --state open --json number --jq '.[].number' \
  | while read -r n; do gh api "repos/<owner>/<repo>/issues/$n" --jq '.title'; done

# 跨仓库拼出选择器：repository 字段导出为 {name, nameWithOwner}
gh search issues "help wanted" --limit 10 --json number,repository \
  --jq '.[] | .repository.nameWithOwner + "#" + (.number | tostring)'
```

`gh search issues`/`gh search prs` 的 `--json repository` 字段导出为含 `name` 与 `nameWithOwner` 的对象，配合编号可拼出 `<owner>/<repo>#<编号>` 形式或 REST 路径，再交给 `gh api` 取详情；详情字段以 REST API 文档为准。要成型的报表优先用 `--template`（步骤 3），要聚合统计再考虑 `--slurp` 加外部 jq。

### 7. 脚本认证：GH_TOKEN 与 gh auth token

```sh
export GH_TOKEN="$(gh auth token)"
gh api repos/{owner}/{repo}/releases --jq '.[0].tagName'
```

脚本与非交互环境优先用 `GH_TOKEN` 提供令牌（`GITHUB_TOKEN` 作为回退）：目标为 `github.com` 或其 `ghe.com` 子域名时生效，设置后不再提示登录，并优先于已存储的凭据；GitHub Enterprise Server 主机改用 `GH_ENTERPRISE_TOKEN`（`GITHUB_ENTERPRISE_TOKEN` 回退）。[gh auth token](cli:command:auth/token) 打印 gh 在指定主机与账号上实际使用的令牌，其查找顺序（环境变量 → 配置文件 → 系统凭据管理器）与 gh 取用顺序一致，适合把令牌转交给其他工具。令牌以明文输出，注意终端历史与日志；令牌类环境变量只影响读取顺序，不会写入配置。

**状态变化一览：**

| 命令 | 远端数据 | 本地状态 | 输出 |
| --- | --- | --- | --- |
| `gh api`（GET／graphql） | 只读 | 不修改 | JSON 或原样响应，经 `--jq`/`--template` 加工 |
| `gh api`（POST／PATCH／DELETE 等） | 按端点语义变更 | 不修改 | 响应体 |
| `gh api --paginate` | 多页读取（方法不变） | 不修改 | 各页顺序输出，或 `--slurp` 合并为一个数组 |
| `gh search issues`／`prs`／`repos`／`code` | 只读 | 不修改 | 表格，或 `--json` 导出数组 |
| `gh auth token` | 只读 | 不修改 | 明文令牌 |

**风险与边界：** `gh api` 带写方法的请求即时生效，没有确认步骤，脚本应先 dry-run 核对端点与载荷。`--paginate` 只支持 GET 与 graphql；GitHub 搜索 API 的结果上限是 1000 条，批量拉取还须自行处理速率限制。`--jq` 逐页应用，跨页聚合必须 `--slurp`（不能与 `--jq`/`--template` 同用）。`GH_TOKEN` 优先于已存凭据：在交互开发机上导出后，它会覆盖正常的登录身份，用完应取消导出。`gh search code` 的结果来自旧版搜索引擎，与网页端可能不一致。
