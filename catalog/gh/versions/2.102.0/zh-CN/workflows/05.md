**适用场景：** 面向在仓库里日常处理议题的维护者与贡献者：先搭好标签体系，再创建、筛选、编辑、关闭议题，处理置顶与跨仓库转移，最后为议题建立关联分支进入开发。

## 前提

- 已安装 gh 2.102.0，并已完成 [gh auth login](cli:command:auth/login) 认证。
- 在目标仓库的 Git 检出内运行，仓库从当前远程推断；也可用 `-R`/`--repo` 或 `GH_REPO` 显式指定。下文以 `<owner>/<repo>` 表示仓库，议题用编号（如 `23`）或 URL 指定。
- 把议题加入或移出项目需要令牌具有 `project` scope（`gh auth refresh -s project`）；`@copilot` 指派在 GitHub Enterprise Server 上不支持。

## 步骤

### 1. 建立标签体系

```sh
gh label create bug --description "Something isn't working" --color E99695
gh label edit bug --color FF0000
gh label clone <owner>/<source-repo>
```

[gh label create](cli:command:label/create) 以指定名称创建标签，`--color` 须为 6 位十六进制色值（开头的 `#` 会自动去掉），未给时随机选择；同名标签已存在时创建失败，确认后用 `--force` 改为更新该标签的颜色与描述。[gh label edit](cli:command:label/edit) 修改名称、描述或颜色，三个修改选项至少给一个，否则报错。[gh label clone](cli:command:label/clone) 把源仓库的全部标签复制到当前仓库（`--repo` 指定其他目的仓库）：默认跳过同名标签，`--force` 改为覆盖；目的仓库中源仓库没有的标签不会被删除或修改。

### 2. 创建议题

```sh
gh issue create --title "登录失败" --body "复现步骤：……" --label bug
gh issue create --template "Bug Report"    # 交互流程中以模板起步
gh issue create --web
```

[gh issue create](cli:command:issue/create)（别名 `gh issue new`）默认从当前远程推断目标仓库。非交互运行必须同时给出 `--title` 与正文（`--body` 或 `--body-file`），否则报错；`--template` 只在交互流程中作为正文起步文本，不能与 `--body`/`--body-file` 同用，单独给出的非交互运行同样会因缺正文而报错。`--web` 改为在浏览器中创建：完全未填标题、正文且仓库配有议题模板时，直接打开模板选择页。`--label`、`--assignee`（支持 `@me`）、`--milestone`、`--project` 可在创建时一并设置。创建成功后向标准输出打印新议题的 URL。

### 3. 两种查看视角

```sh
gh issue status
gh issue status --json title,state --jq '.assigned[].title'
gh issue list --state all --label bug
gh issue list --search "error no:assignee sort:created-asc"
```

[gh issue status](cli:command:issue/status) 是"与我相关"的视角，分三组列出指派给你的、提及你的、你创建的议题；`--json` 输出按 `assigned`、`mentioned`、`createdBy` 三个键组织，`--jq` 在此之上取字段。[gh issue list](cli:command:issue/list)（别名 `gh issue ls`）是按条件筛选的视角：默认只列开启状态，`--limit` 默认 30；`--assignee`（`@me` 表示自己）、`--author`、`--app`、`--milestone`、`--type`、`--search` 等组合过滤。注意：给出 `--search`，或给出 `--label`、`--milestone`、`--type` 时改走搜索 API，结果上限 1000 条。

### 4. 编辑议题

```sh
gh issue edit 23 --add-label "help wanted" --remove-label bug
gh issue edit 23 --add-assignee "@me"
gh issue edit 23 34 --add-label "help wanted"
```

[gh issue edit](cli:command:issue/edit) 接受一个或多个议题选择器（编号与 URL 可混用，但所有议题必须属于同一仓库）；不给出任何编辑旗标时进入交互模式，交互模式仅支持单个议题。批量编辑时不能进入交互模式，也不能用 `--add-sub-issue` 与 `--attach`。成功编辑的议题 URL 排序后输出到标准输出，失败的议题输出到标准错误且命令以非零退出码结束——批量操作后应核对这两部分输出。

### 5. 关闭、重开与重复标记

```sh
gh issue close 23 --reason "not planned"
gh issue close 23 --duplicate-of 45
gh issue reopen 23 --comment "已在新版本修复"
```

[gh issue close](cli:command:issue/close) 默认不设置关闭原因；`--reason` 取 `completed`、`not planned`、`duplicate`。`--duplicate-of` 把议题标记为另一议题的重复并隐含 duplicate 原因，指向对象必须是议题（不能是拉取请求或议题自身）。编号实际指向拉取请求时，本命令改为关闭该拉取请求——执行前先确认编号指向。[gh issue reopen](cli:command:issue/reopen) 的 `--comment` 在重新打开前先行提交。

### 6. 置顶与转移

```sh
gh issue pin 23
gh issue unpin 23
gh issue transfer 23 <owner>/<other-repo>
```

[gh issue pin](cli:command:issue/pin) 与 [gh issue unpin](cli:command:issue/unpin)：议题已处于目标状态时输出提示、不做更改并正常结束，重复执行无害；置顶状态可通过支持 `--json` 的命令用 `isPinned` 字段查看。[gh issue transfer](cli:command:issue/transfer) 把议题转移到目标仓库（`DESTINATION-REPO`，未显式包含主机时沿用议题所在仓库的主机），成功后向标准输出打印议题在新仓库的 URL，后续命令应改用新 URL；拉取请求不能转移，遇到时报错。

### 7. 关联分支开发

```sh
gh issue develop 23 --checkout
gh issue develop --list 23
```

[gh issue develop](cli:command:issue/develop) 默认为议题创建关联分支，成功后输出分支 URL（形如 `<host>/<owner>/<repo>/tree/<branch>`）；`--name` 指定分支名（未给时自动生成，名称与既有关联分支一致时直接复用），`--base` 指定起点远程分支并记录为之后 `gh pr create` 的基分支，`--checkout` 创建后同时检出，`--worktree` 检出到指定路径（须与 `--checkout` 同用）。`--list` 改为列出现有关联分支，与各创建侧选项互斥。

**状态变化一览：**

| 命令 | 议题 | 标签体系 | 其他 |
| --- | --- | --- | --- |
| `gh label create`／`gh label edit` | 不涉及 | 创建／修改标签 | 同名创建失败，`--force` 改为更新 |
| `gh label clone` | 不涉及 | 复制源仓库全部标签 | 默认跳过同名；`--force` 覆盖 |
| `gh issue create` | 创建新议题 | 可同时打标签 | 输出新议题 URL |
| `gh issue status`／`gh issue list` | 只读 | 只读 | 不改变任何状态 |
| `gh issue edit` | 修改标题、正文、指派人等 | 增删标签 | 支持一次编辑多个议题 |
| `gh issue close`／`gh issue reopen` | 状态切换 | 不涉及 | 关闭原因与评论可选 |
| `gh issue pin`／`gh issue unpin` | 置顶状态 | 不涉及 | 幂等，重复执行只提示 |
| `gh issue transfer` | 归属仓库变化 | 不涉及 | 输出新仓库 URL |
| `gh issue develop` | 记录分支关联 | 不涉及 | 在目标仓库创建分支 |

**风险与边界：** `gh issue close` 的编号指向拉取请求时会改为关闭该拉取请求，`--duplicate-of` 对拉取请求不可用。`gh issue transfer` 成功后议题归属新仓库、获得新 URL，转移前应确认目标仓库。`gh label clone --force` 会以源仓库标签覆盖目的仓库同名标签，且不会删除目的仓库多出的标签。批量 `gh issue edit` 允许部分失败（失败项走标准错误、退出码非零），不要把退出码非零理解为全部失败。创建失败的输入可用 `--recover` 恢复，但它仅支持交互式运行。
