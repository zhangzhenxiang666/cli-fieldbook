**适用场景：** 从零开始一个 Rust 包：用 `cargo new` 按模板与版本控制偏好生成项目骨架，`cargo check` 做不带代码生成的快速验证，`cargo run` 构建并运行二进制目标，`cargo test` 建立单元、集成与文档测试的回归基线；并说明每步的完成信号与 `target` 目录中出现的产物。

## 前提

- 已安装随 Rust 1.99.0 发布的 cargo 1.99.0，`cargo --version` 应自称 `cargo 1.99.0`。
- [cargo new](cli:command:new) 要求目标目录不存在；在已有目录补建清单改用 [cargo init](cli:command:init)。
- 未特别说明时，命令在项目的父目录或项目根目录执行；`<name>` 表示包名。

## 步骤

### 1. 新建二进制包

```sh
cargo new hello_world
```

[cargo new](cli:command:new) 在给定路径创建包，成功时输出 ``Creating binary (application) `hello_world` package``，生成 `Cargo.toml`、`src/main.rs` 与 VCS 忽略文件。模板与默认值（依据 `cargo_new.rs`）：

- 模板：默认二进制（`--bin` 即默认），生成 `src/main.rs`；`--lib` 改用库模板生成 `src/lib.rs`，两者互斥，同时给出报错。
- VCS：目标目录不在已有 VCS 仓库中时默认初始化一个 git 仓库；已在仓库内则不嵌套建库，只写忽略文件。`--vcs` 显式选择 `git`、`hg`、`pijul`、`fossil` 或 `none`；忽略文件内容为 `/target`（各 VCS 使用对应语法）。
- 清单：包名默认取目录名（`--name` 覆盖），版本固定 `0.1.0`，`edition` 未指定时取本版 cargo 支持的最新稳定 edition（快照书示例写为 `2024`），`--edition <YEAR>` 显式指定。
- `Cargo.lock` 此时不会创建，它在第一次构建类命令运行时生成。

目标目录已有源码、或希望就地初始化时，改用下面的 init。

### 2. 在已有目录初始化（可选）

```sh
cargo init
# 说明性示例：把当前目录初始化为库包
cargo init --lib
```

[cargo init](cli:command:init) 在当前目录（或给定路径）补建清单，差异在于：目录中已有的典型源文件（`src/main.rs`、`src/lib.rs`）会被沿用而不是覆盖；既无 `--bin` 也无 `--lib` 时按已有源文件推断包种类；目录中已有 `Cargo.toml` 则拒绝执行；检测到多个 VCS 元数据目录（如同时有 `.git` 与 `.hg`）时报错并要求 `--vcs` 显式指定。VCS 与 edition 的默认值与 `cargo new` 相同。

### 3. 快速验证

```sh
cargo check
```

[cargo check](cli:command:check) 编译本包与全部依赖但不执行最终代码生成，因此快于 [`cargo build`](cli:command:build)；编译器把元数据写入 `target` 目录，源码未变时后续命令复用。完成信号：输出 `Finished` 行且退出码为 `0`（退出码语义见[退出代码](../reference/exit-codes.md)）。注意：只在代码生成阶段出现的诊断（如部分链接错误）不会在 check 中报告，通过 check 不等于能通过 build 或 run。

### 4. 运行

```sh
cargo run
# 说明性示例：-- 之后的所有参数传给被运行的程序
cargo run -- --verbose
```

[cargo run](cli:command:run) 先按默认 dev profile 构建再执行。行为要点（依据 `cargo_run.rs`）：

- 只有一个二进制目标时直接运行；存在多个时必须用 `--bin <NAME>` 选择（或在清单写 `default-run`），否则报错并列出可用二进制；`--example <NAME>` 改为运行示例目标。
- 被运行程序的工作目录就是当前工作目录，与 shell 直接执行一致；其退出码原样作为 cargo 的退出码返回。
- ``Running `target/debug/hello_world``` 状态行给出实际执行的文件；`-r`/`--release` 时产物改在 `target/release/`。

### 5. 建立回归基线

```sh
cargo test
# 说明性示例：按名字过滤、只在单个集成测试内精确运行一个用例
cargo test parse
cargo test --test int_test_name -- modname::test_name
```

[cargo test](cli:command:test) 编译并运行单元测试、`tests/` 目录下的集成测试与文档测试，同时编译 examples 确认其可编译（书《Tests》）。要点：

- 第一个位置参数 `TESTNAME` 是传给测试框架的过滤串，按子串匹配测试名；`--` 之后的参数进入 libtest，例如 `cargo test foo -- --test-threads 3`。
- 包含多个测试目标时各目标依次串行执行；`--no-fail-fast` 让失败目标不中断后续目标，失败与统计在结束时汇总。
- 任一测试目标失败时，该目标的退出码成为 cargo 的退出码（见[退出代码](../reference/exit-codes.md)），全部通过时为 `0`。
- 测试与基准的工作目录是所属包的根目录（与 run 不同），测试内可用相对路径访问包内文件；`--doc` 只运行文档测试，libtest 的完整参数可用 `cargo test -- --help` 查看。
- `--workspace`（别名 `--all`）覆盖整个工作区，`--no-fail-fast` 配合可在 CI 中一次收集全部失败。

**状态变化一览：**

| 命令 | Cargo.toml | Cargo.lock | target 目录 |
| --- | --- | --- | --- |
| `cargo new` / `cargo init` | 创建 | 不创建 | 不创建 |
| `cargo check` | 只读 | 首次生成 | `debug/deps/` 下 `.rmeta` 元数据 |
| `cargo run` | 只读 | 首次生成 | `debug/<name>` 可执行文件 |
| `cargo test` | 只读 | 首次生成 | `debug/deps/` 下各测试可执行文件 |

**风险与边界：** check 的"通过"只覆盖到类型检查为止，链接与代码生成问题推迟到 build/run 才暴露。test 会触发文档测试与 examples 编译，新增失败可能来自 doctest 而非单元测试；`--` 两侧参数分别属于 cargo 与被运行程序，位置放错是最常见的误用。`target` 目录可随时用 [`cargo clean`](cli:command:clean) 清空，删除后下次构建全部重来。
