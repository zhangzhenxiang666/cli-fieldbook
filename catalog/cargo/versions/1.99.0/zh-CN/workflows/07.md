**适用场景：** 用 `cargo install` 把带命令行目标的 crate 安装为本机可用工具：从注册表、git 或本地路径安装，选定版本与二进制，理解安装位置与重装条件，用 `uninstall` 干净移除；并厘清它与 rustup 工具链管理的边界。

## 前提

- 只有含可执行 `[[bin]]`（或 `--example`）目标的包可被安装；安装是机器级操作，配置发现从 `$CARGO_HOME/config.toml` 开始，忽略项目级配置（`--path` 安装除外，man 手册《Configuration Discovery》）。
- `<crate>` 表示 crate 名，`<version>` 表示 SemVer 版本；希望 `$ cargo install xxx` 之后能直接敲 `xxx`，需要安装根的 `bin` 目录在 `$PATH` 中。
- 本页不涉及 rustup 对工具链的安装与管理，见文末边界。

## 步骤

### 1. 从注册表安装

```sh
cargo install ripgrep
# 说明性示例：指定版本、只装一个二进制
cargo install ripgrep --version 14.1.0
cargo install foo --bin foo-cli
```

[cargo install](cli:command:install) 默认从 crates.io 解析最新版本，编译其可执行目标并安装。源里有多个包时（crates.io 检索或含多 crate 的 git 仓库）必须给出 crate 名指定装哪个；一个包有多个二进制时 `--bin` 挑选，`--example` 改装示例目标（默认不装）。`--version`（别名 `--vers`）限定版本，仅用于注册表来源。

### 2. 从 git 或本地路径安装

```sh
# 说明性示例：git 固定 tag；本地路径；连同打包锁文件一起用
cargo install --git https://github.com/BurntSushi/ripgrep --tag 14.1.0 ripgrep
cargo install --path .
cargo install --path . --locked
```

- git 来源用 `--git <URL>`，`--branch`/`--tag`/`--rev` 三选一固定引用，缺省为默认分支最新提交；误把 URL 当 crate 名传入时 cargo 会提示改用 `--git`（`install.rs` 的参数检查）。
- `--path`（或省略来源参数、在项目目录内执行）从本地源码构建安装。
- `--locked` 让安装使用包内打包的 `Cargo.lock`，复现发布时的依赖选择；缺省时忽略包内锁文件、按清单重新解析（可能取到更新的依赖）。注意 cargo 自 1.37 起才随包发布锁文件，更早的包没有锁文件可用。

### 3. 确认安装位置与已装清单

```sh
cargo install --list
```

可执行文件安装到安装根的 `bin` 目录。安装根按优先级取：`--root <DIR>` > `CARGO_INSTALL_ROOT` 环境变量 > `install.root` 配置 > `$CARGO_HOME`（默认 `~/.cargo`），因此默认位置是 `$CARGO_HOME/bin`（man 手册与《Cargo Home》）。`--list` 列出安装根下已装的每个包及其版本和二进制名，输出形态（说明性示例）：

```console
ripgrep v14.1.0:
    rg
```

安装状态记录在 `$CARGO_HOME` 的 `.crates.toml`/`.crates2.json`（不要手改）；`--list` 正是读取这份记录，而非扫描 `bin` 目录。

### 4. 升级与强制重装

```sh
# 说明性示例：重装到最新；名字冲突时强制覆盖
cargo install ripgrep
cargo install ripgrep --force
```

已安装的包在以下任一项变化时才重装：包版本与来源、安装的二进制名集合、所选特性、profile（`--profile`）、目标三元组（man 手册）。从 crates.io 或 git 安装时目标目录默认是临时目录，重装即全量重编；`CARGO_TARGET_DIR` 可指定缓存目录（见[环境变量](../reference/environment.md)）。`--path` 安装总是重新构建安装。不同包装出同名二进制会冲突，需 `--force` 覆盖或改用 `--bin` 避开。

### 5. 移除

```sh
cargo uninstall ripgrep
# 说明性示例：只移除一个二进制；指定安装根
cargo uninstall ripgrep --bin rg
cargo uninstall --root /opt/tools ripgrep
```

[cargo uninstall](cli:command:uninstall) 删除该包安装出的二进制文件并更新 `.crates.toml`/`.crates2.json` 记录；默认移除该包全部二进制，`--bin` 只移除指定的。参数是包 ID 规范（工作流 08 的 SPEC 语法）。

**状态变化一览：**

| 命令 | 安装根 bin 目录 | `.crates.toml`/`.crates2.json` | 项目 target 目录 |
| --- | --- | --- | --- |
| `cargo install <crate>` | 写入二进制 | 登记安装项 | 默认临时目录（`--path` 用项目自身） |
| `cargo install --list` | 只读 | 只读 | 不涉及 |
| `cargo uninstall <spec>` | 删除对应二进制 | 移除安装项 | 不涉及 |

**与 rustup 的边界：** `cargo install` 管理的是"用 cargo 装二进制 crate"，不安装也不切换 rustc/cargo 工具链；`cargo +<toolchain> install ...` 中的 `+toolchain` 前缀由 rustup 拦截处理，不属于 cargo 的参数（把它误当包名传入时 cargo 会提示）。rustup 自身安装的工具（如 `cargo-fmt`）也放在同一个 `bin` 目录里（书《Cargo Home》），所以 `cargo uninstall` 不应也不能移除它们——它只认自己记录在 `.crates.toml` 的安装项。

**风险与边界：** 安装会完整编译目标包及其依赖，耗时与磁盘占用远高于包管理器的二进制安装；不要用 `cargo install` 管理系统级服务。`--force` 覆盖同名二进制时不会提示被覆盖的是哪个包，先 `--list` 核对。`-n`/`--dry-run` 在本版存在但属 nightly `-Z unstable-options` 门控，稳定通道不可用。
