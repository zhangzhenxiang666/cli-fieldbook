---
title: "Examples / 用同一张图分清 :: 与 .."
---

以下字母代表提交，不代表顺序编号。图从下往上推进，D 有 B、C 两个父：

```text
      D
     / \
    B   C
     \ /
      A
      |
    root()
```

| 表达式          | 结果集合             | 理由                |
| ------------ | ---------------- | ----------------- |
| `D-`         | `{B, C}`         | 合并的两个直接父          |
| `D--`        | `{A}`            | 两条父路径最后去重         |
| `::B`        | `{root(), A, B}` | 包含自身的祖先           |
| `..B`        | `{A, B}`         | 相同祖先但排除虚拟根        |
| `B::`        | `{B, D}`         | 从 B 向后走           |
| `B..`        | `{C, D}`         | 排除 B 的全部祖先，不是只向后走 |
| `B::D`       | `{B, D}`         | 在 B 的后代与 D 的祖先交集中 |
| `B..D`       | `{C, D}`         | D 的祖先减去 B 的祖先     |
| `B::C`       | `{}`             | B 不是 C 的祖先        |
| `B..C`       | `{C}`            | 不要求 B、C 存在祖先关系    |
| `D..`        | `{}`             | 这张图所有提交都是 D 的祖先   |
| `(B \| C)..` | `{D}`            | 同时排除两组祖先          |
| `B.. \| C..` | `{B, C, D}`      | 与上一行不同            |

集合顺序不重要。核心区别：

```text
B::D  ——“沿着 B 到 D 的祖先关系，取路径上的提交”
B..D  ——“D 已包含，而 B 还没有包含的提交”
```

因此，整理主线以外的历史时常用 `trunk()..@`；但不要把它解释为“主线与 @ 之间的一条直线”。

还有一个常见代数陷阱：

```text
(A | B).. = A.. & B..
(A | B).. != A.. | B..
```

这是从祖先并集取补集所产生的交集关系。此页结果已用独立的小型 DAG 集合模型检查，但这不是执行 jj 二进制的结果。
