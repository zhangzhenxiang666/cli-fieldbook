**适用场景：** 当前 @ 已经是一个工作副本提交。修改文件后，用 jj 命令观察和记录快照；不用照搬 git add → git commit。

```sh
jj status
jj diff
jj describe -m "feat: add request validation"
jj new

# 更短的替代流程；不要与上面的 describe + new 重复执行
# jj commit -m "feat: add request validation"

jj log -r 'trunk()..@'
```

**执行结果：** describe 为当前 change 写描述；new 创建并切换到新的空孩子。执行完后，上一项工作的 change 是 @-，新工作 change 是 @。

**风险与边界：** new 并不保证替你把既有书签前进。commit 还支持按路径/交互选择，其语义不只是给当前提交改标题。merge 的 @- 可能是多个父提交。
