**适用场景：** 准备把当前功能分支及后代放到最新主线之上。trunk() 必须在本仓库解析为你预期的主线。

```sh
jj git fetch --remote origin
jj log -r 'trunk() | trunk()..@'
jj rebase -b @ -o 'trunk()'
jj status
jj resolve --list
```

**执行结果：** -b 按相对于目标的分叉关系选择分支；它不是 -s 和 -r 的简单拼写变化。发生冲突时，冲突可以作为提交内容保存在图中，再单独解决。

**风险与边界：** 先看 log 确认范围。多主线、多 merge 或已有独立 change 的仓库，默认 -b @ 不一定就是你脑中的“一个提交”。远端引用缓存先 fetch 更新。
