**适用场景：** 二选一。新项目从远端克隆；已有 .git 的项目只增加 jj 元数据。以下身份和仓库地址必须替换成你自己的值。

```sh
# 先配置身份（不是 GPG/SSH 签名配置）
jj config set --user user.name "你的名字"
jj config set --user user.email "you@example.com"

# 方案 A：克隆；显式写出并置布局，避免受个人默认配置影响
jj git clone --colocate https://example.com/team/project.git project
cd project

# 方案 B：不要紧接着执行 A；在已有 Git 仓库根目录运行
# jj git init --colocate

jj status
jj log
jj git remote list
```

**执行结果：** 并置布局中 .jj 与 .git 共存。后续主要使用 jj，仍可被需要 .git 的工具识别。

**风险与边界：** v0.45.1 的内置 git.colocate=true；旧教程的默认值可能不同。现有 Git index、工作区和引用应先检查，不要把初始化当作清理修改的命令。额外 workspace 在这一版不支持 colocation。
