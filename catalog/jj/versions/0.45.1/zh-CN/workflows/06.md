**适用场景：** squash 用于明确知道修改该归入哪一项工作；absorb 则根据行的历史归属自动分配给可变祖先。

```sh
# 方案 A：把当前修复放入明确目标，可交互选择片段
jj squash --into CHANGE_A -i

# 方案 B：替代方案，让 jj 根据行归属分配
# jj absorb --from @ --into 'mutable()'

jj op show -p
jj status
```

**执行结果：** squash 的 --into 修改已有目标；absorb 仅考虑来源的祖先，不能明确归属的改动留在来源。用 op show -p 审阅这次操作的整体效果。

**风险与边界：** 不要将 squash --onto 与 --into 视为同义：前者是创建新目标提交的实验性模式。absorb 不是语义级 AI 归类，新增/混合改动可能无法自动归位。
