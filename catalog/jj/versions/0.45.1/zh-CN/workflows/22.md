**适用场景：** 已知 GOOD_REV 正常、BAD_REV 有问题，且该问题在所选历史上近似单调。建议在单独 workspace 中执行。

```sh
# 先进入专用于排查的工作区；把两个占位符替换为实际修订
jj bisect run --range 'GOOD_REV..BAD_REV' -- cargo test
```

**执行结果：** 范围之外的祖先视为 good，范围的 heads 视为 bad。每次测试会直接把被测提交设为当前工作副本；0 为 good，125 为跳过，127 中止，其余非零为 bad。

**风险与边界：** 这不是 run 的隔离目录模型。测试必须能可靠地表达目标故障，编译失败也会被当成 bad，除非脚本主动返回 125。虽然 Usage 中 COMMAND 带方括号，实际运行必须提供命令或已弃用 --command。
