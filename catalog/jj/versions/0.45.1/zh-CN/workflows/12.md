**适用场景：** 当前工作完成后，把既有 feature-validation 书签前进到最新完成的提交，再按预期远端状态推送。

```sh
jj describe -m "feat: extend request validation"
jj new
jj bookmark advance feature-validation --to @-

jj git fetch --remote origin
jj bookmark list -a
jj git push --remote origin -b feature-validation --dry-run
jj git push --remote origin -b feature-validation
```

**执行结果：** 显式提供书签名和 --to 可以避免 bookmark-advance-from 配置选择到其他书签。push 检查远端引用是否与本地已知状态相符。

**风险与边界：** fetch 后出现书签分歧时，应先审查并选择/整合正确历史；不要仅为了消除报错直接使用 --allow-backwards。jj 没有通用 git push --force 对应流程。
