---
title: 04. 堆叠提交：回头修正中间的一层
uses:
  - "command:"

  - command:edit
  - command:log
  - command:new
  - command:squash
---

**适用场景：** 已有 A → B → C 的未发布堆叠，在最顶层继续开发时发现 A 中遗漏了修改。CHANGE_A 换成 A 的实际 change ID。

```sh
TOP=$(jj log -r @ --no-graph -T 'change_id ++ "\n"')

# 在 A 上方新建一个临时修复 change
jj new CHANGE_A
# 编辑只属于 A 的修复
jj diff
jj squash --into CHANGE_A

# 继续回到原堆叠顶端
jj edit "$TOP"
jj log -r 'trunk()..@'
```

**执行结果：** 修复压入 A 后，依赖 A 的后代会相应重写；不必先把整个堆叠交互式 rebase 成 Git 的编辑状态。

```text
原来：base -> A -> B -> C
修改：base -> A' -> B' -> C'
A/B/C 的 change ID 通常保持；commit ID 随对象重写而变化。
```

**风险与边界：** 如果 A 或其需重写的后代受 immutable 保护，命令会拒绝。不要习惯性加 --ignore-immutable；先判断是否已经发布以及是否影响他人。
