**适用场景：** 整仓库工具适合 run；按文件从标准输入接收内容并输出替代内容的转换器适合 fix。这里只使用未发布、可重写的修订。

```sh
# 格式化每个修订，并把结果写回相应 change
jj run -r 'trunk()..@ & mutable()' --root -- cargo fmt --all
jj op show -p
jj run -r 'trunk()..@' --root --ignore-changes -- cargo test

# 已配置 fix.tools 时的另一条路径：
# jj fix -s CHANGE_A
```

**执行结果：** 不带 --ignore-changes 的 run 可以把外部程序修改写回提交；fix 依据文件内容调用已配置工具，能按相同路径/内容去重处理。

**风险与边界：** 先审阅选中的修订范围。工具必须值得信任；格式化后仍可能产生冲突或影响后代。--restore-descendants 的“保持后代文件树”不等价于默认重放后代补丁；不要无意识混用。
