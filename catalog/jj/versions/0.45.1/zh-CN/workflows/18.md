**适用场景：** 为评审、实验或另一项功能开一个目录，共享同一仓库对象和引用，但有独立的 @。

```sh
# 显式以当前 @ 为父，创建名为 review 的新工作区
jj workspace add ../project-review --name review -r @
jj workspace list

cd ../project-review
jj status
jj new 'trunk()'

# 若 jj 明确报告工作区过期，再运行：
# jj workspace update-stale
```

**执行结果：** 额外 workspace 与主工作区共享提交/书签，不等于另一个完全独立 clone。省略 add 的 -r 时，新工作 change 默认与当前工作 change 共享父，而非以当前 @ 为父。

**风险与边界：** workspace forget 只移除管理记录，不删除磁盘目录；删除目录是另一个动作。不要跨工作区并行覆盖同一外部生成文件。v0.45.1 不支持额外 workspace 的 colocation。
