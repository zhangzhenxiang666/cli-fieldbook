**适用场景：** 以下从当前 @ 为已完成且非空的工作 change 开始。先 new，确保书签指向完成的 @-，而不是新的空工作 change。

```sh
jj describe -m "feat: add request validation"
jj new
jj bookmark create feature-validation -r @-
jj bookmark list

jj git push --remote origin -b feature-validation --dry-run
# 核对上一步计划后，再推送
jj git push --remote origin -b feature-validation
```

**执行结果：** 书签是对外发布的名称。新建一个本地 change 不等于为远端创建一个分支；这里明确选择一个书签，避免默认推送范围的歧义。

**风险与边界：** 若书签已经存在，改用 bookmark set 或 advance，不要再次 create。merge 的 @- 可能不唯一；这时明确给出完成工作的修订。--dry-run 是 push 的局部选项。
