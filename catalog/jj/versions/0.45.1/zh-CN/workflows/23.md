**适用场景：** 发布目标 RELEASE_REV 已通过测试。签名先于打标签，避免标签的不可变保护与历史重写互相冲突；签名后端须预先配置。

```sh
# 可选：已经配置签名后端时
# jj sign -r RELEASE_REV

jj tag set v1.2.3 -r RELEASE_REV
jj tag list
jj git push --remote origin --tag v1.2.3 --dry-run
# 确认目标和计划后：
# jj git push --remote origin --tag v1.2.3
```

**执行结果：** tag 是发布引用，set 默认不允许悄悄移动已有标签。sign/unsign 都会重写提交对象，不是给本地标签附加一段注释。

**风险与边界：** 不要把 --allow-move 当作常规发布选项，也不要把 jj 的提交签名误认为 Git annotated-tag 签名。发布后需要改内容，通常用新版本，而不是重用版本号。
