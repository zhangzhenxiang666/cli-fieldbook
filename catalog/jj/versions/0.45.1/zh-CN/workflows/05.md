title: 05. 一次改太多：把功能与重构拆开

---

**适用场景：** 当前 @ 同时包含两项逻辑工作。先通过交互界面选出第一项；或者用路径选择整个目录。

```sh
jj diff
jj split -i -m "refactor: extract validation helpers"
jj log -r 'trunk()..@'
jj diff

# 路径选择是替代方案，不要紧接着再次拆分
# jj split src/validation/ -m "refactor: extract validation helpers"
```

**执行结果：** 默认选中的部分保留在原 change，余下部分成为它的新孩子。用 --parallel 可创建兄弟提交；指定 -o/-A/-B 时则采用提取到指定位置的语义。

**风险与边界：** 交互式 diff editor 中通常通过调整右侧来表达所选改动，不是简单选择文件保存。书签行为受 split.legacy-bookmark-behavior 控制，拆分后必须检查 bookmark list。
