**适用场景：** 想把一个提交的补丁复制到当前主线上，原提交和原分支保持不动。

```sh
jj duplicate CHANGE_A -o 'trunk()'
jj log

# 从上一条命令输出中取得新 change ID 后，才运行这一行
# jj edit NEW_CHANGE_ID
```

**执行结果：** duplicate 会生成新的 change ID；rebase 则是移动/重写原有 change。指定多个修订可以复制一组改动。

**风险与边界：** duplicate 不等于自动切换到新工作 change。源提交可以来自已发布历史，但复制后的补丁仍可能冲突；检查图和内容。
