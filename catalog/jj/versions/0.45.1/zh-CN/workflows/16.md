**适用场景：** 已合并的某个提交有问题，需要保留审计历史，新增撤销补丁，而不是 abandon 或重写公共历史。

```sh
jj revert -r BAD_CHANGE -o 'trunk()'
jj log

# 取得新反向 change 的 ID 后检查
# jj show NEW_REVERT_CHANGE
# jj new NEW_REVERT_CHANGE
```

**执行结果：** revert 生成反向补丁对应的新修订。它和 op revert 完全不同：前者反转提交内容，后者反转一次仓库操作。

**风险与边界：** v0.45.1 必须同时指定待反转的 -r 和放置位置 -o/-A/-B。多个源修订按逆拓扑顺序处理，可能出现冲突；创建后不要假设 @ 自动切换。
