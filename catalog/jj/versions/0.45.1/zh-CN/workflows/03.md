**适用场景：** 当前有未完成的功能，先给它一个清晰描述和稳定 change ID，再切到主线处理紧急修复。

```sh
jj describe -m "wip: request validation"
WIP=$(jj log -r @ --no-graph -T 'change_id ++ "\n"')

jj new 'trunk()' -m "fix: handle missing configuration"
# 编辑文件并测试紧急修复
jj diff
jj new

# 回到原来的工作 change
jj edit "$WIP"
```

**执行结果：** 两项工作成为不同的 change；回到 WIP 时可以继续原来的文件状态。change ID 通常在重写前后保持，commit ID 则会改变。

**风险与边界：** 忽略、未跟踪或无法快照的文件不因此得到保护；不能把 jj 当作整个目录的备份工具。分歧 change ID 需要进一步消歧。
