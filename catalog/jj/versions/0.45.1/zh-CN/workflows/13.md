**适用场景：** 先决定是希望删除远端分支，还是仅清理本机的命名/跟踪状态。以下只有方案 A 是主动准备远端删除。

```sh
jj bookmark list -a

# 方案 A：删除本地书签，并审阅将同步出去的删除
jj bookmark delete feature-old
jj git push --remote origin --deleted --dry-run
# 确认列表中每一项都应删除后才运行：
# jj git push --remote origin --deleted

# 方案 B：替代方案，只忘记本地书签
# jj bookmark forget feature-old

# 方案 C：替代方案，停止跟踪一个远端书签
# jj bookmark untrack feature-old@origin
```

**执行结果：** delete 表示本地删除意图可通过 push 传播；forget 不表示要把远端分支删掉；untrack 改变跟踪关系。

**风险与边界：** --deleted 可能覆盖多个待删除引用，不只示例中的一个。先审阅 dry-run。forget 后再次 fetch 的结果取决于保留的远端引用与自动跟踪配置。
