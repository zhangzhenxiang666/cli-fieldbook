# 首版范围与审核信任边界

2026-10-02：采用原设计的第一阶段，首版交付两工具迁移、固定来源、站点、搜索、合订 Markdown 与 Pages。自动采集、真实版本升级机器人、其他导出格式和新增语言留待后续。

内容交换协议以 JSON Schema 为权威，Astro frontmatter 只是生成层格式。未知默认值缺省；旧资料中只有中文释义而未完成字段级抽取的默认值，不显示为“上游未说明”，应引导读者查看释义。源码文件按原始字节保存在 `.txt` 快照中，不作为程序执行。

本地 jj 与 Git 并置，供需要 .git 的工具识别；本地版本操作仍用 jj。CI checkout 与历史提交校验使用 GitHub Actions 和 Git，不改变贡献者的本地工作流。

pnpm 12 已有内置 docs 命令，因此项目命令固定使用 pnpm run docs。Astro 默认 slug 会移除版本中的点；Starlight 会移除最后一个 index，加载器保留文件名 token，避免将真实 index 命令折叠成父节点。

## 单维护者机制

维护者为 @zhangzhenxiang666。PR 要求检查通过；首版不强制配置一个维护者本人无法满足的独立 PR 批准，不启用自动合并。CODEOWNERS 为后续协作保留分工入口。

Agent 执行机械检查与注明范围的语义审阅，准备正文、事实、来源和依赖指纹。review.lock 状态只能为 prepared；任何作者填写 reviewed 都不能构成可信批准。

最终审核由 GitHub github-pages 环境的 required reviewer 决定，仅允许 main 部署，允许维护者本人确认自己的部署，关闭管理员绕过。批准绑定该工作流、提交、内容清单与产物文件摘要；批准后不执行依赖安装或重新生成正文。公开站点提供对应运行的审批记录链接。

这是用户选择的单维护者发布协议，替代原提案中必须依靠独立 PR 审阅者的首版落地方式；它不将 Agent 的基线准备等同于维护者批准。

## Markdown 与搜索

普通内容拒绝任意 HTML、MDX、脚本和危险协议。历史锚点转换为受控 Markdown 路由，字面占位符转换为代码。命令搜索、Pagefind 搜索和页面共享同一模型；草稿仅进入明确标记的预览。

搜索客户端作为可信静态模块发布，避免 Astro/Vite 对运行时 Pagefind 导入产生失效预加载占位符。所有查询结果用 DOM 文本接口渲染，不执行索引里的 HTML。
